## Cosa entra nel contesto del modello

Ogni richiesta contiene lo schema completo del modulo corrente e il catalogo di creazione form0
installato. Questo contesto completo serve all'agente per preservare la struttura, risolvere i
riferimenti e validare le modifiche tra calcoli, condizioni, sezioni ripetibili ed eventi.

Il modello non riceve:

- valori dei record o invii
- file arbitrari del progetto locale
- il contenuto delle immagini di supporto
- le credenziali dei provider
- accesso a shell, file system, MCP, estensioni o skill di terze parti

Gli attributi dello schema, compresi i percorsi e i metadati IA già presenti nel modulo, fanno parte
dello schema completo e sono quindi inclusi.

## Policy cloud dai metadati dello schema

I [metadati IA](/it/core/ai-metadata) esistenti hanno una semantica che la creazione nella CLI fa
rispettare:

```json
{
  "form": {
    "ai": {
      "allowCloud": false,
      "requiresConsent": true
    }
  }
}
```

Se è presente `form.ai.allowCloud: false` o un qualsiasi `field.ai.allowCloud: false`, tutti i
provider cloud vengono bloccati per quel modulo. I modelli locali restano disponibili. La CLI non
consente di ignorare questa impostazione.

Se il modulo o un campo imposta `requiresConsent: true`, la CLI chiede conferma prima della prima
richiesta cloud della sessione IA e di nuovo dopo un cambio di provider cloud. Altrimenti, entrare
in modalità IA e selezionare o autenticare un provider cloud vale come consenso, dopo che la CLI ha
spiegato che viene inviato l'intero schema.

Usa `/privacy` per controllare la policy effettiva e le voci del modulo o dei campi che la
determinano.

## Credenziali e conversazioni

Lo stato dell'IA si trova in `~/.form0-cli/ai/`, fuori dal progetto. Le directory sono accessibili
solo all'utente corrente; i file di credenziali e conversazioni hanno permessi riservati all'utente.
Le credenziali nelle variabili d'ambiente restano supportate e non vengono copiate negli schemi.

La cronologia della conversazione è associata al percorso canonico dello schema e può contenere lo
schema completo. Usa `/clear` per eliminare la cronologia salvata del modulo corrente. Un modulo non
salvato usa un'identità temporanea, riassegnata dopo la prima applicazione riuscita.

:::warning

Il JavaScript generato per i calcoli e gli eventi del modulo viene validato a livello strutturale,
ma resta codice scritto da un autore. Controlla il diff e il comportamento previsto prima di
applicarlo, soprattutto per i moduli sensibili.

:::

## Accesso limitato alla documentazione

L'agente può richiedere documentazione aggiuntiva solo da `https://docs.form0.dev`. Il recupero
parte da `llms.txt` e segue solo pagine Markdown pertinenti in HTTPS della stessa origine. URL e
reindirizzamenti verso altre origini, contenuti non supportati, risposte troppo grandi e timeout
vengono rifiutati; le risposte riuscite vengono memorizzate nella cache per la sessione.

Il testo recuperato è materiale di riferimento non attendibile. Non può modificare le istruzioni di
sistema, i permessi degli strumenti né la policy cloud. Se la documentazione remota contraddice il
catalogo del form0-core installato, prevale il catalogo installato. Offline, la creazione prosegue
senza documentazione remota.

## Responsabilità del provider

Le richieste cloud vengono inviate direttamente al provider selezionato con la credenziale o
l'abbonamento dell'utente. form0 non fa da proxy per le richieste, non misura l'utilizzo, non
riporta i saldi dei crediti e non controlla la conservazione dei dati da parte del provider.
Consulta i termini e i controlli sui dati attuali del provider selezionato prima di inviare uno
schema.
