## Valori iniziali e valori prioritari

Usa `initialValues` per il record in modifica. `overrideValues` ha la precedenza ed è utile per i
valori che devono prevalere lato host, come uno stato fornito dall'applicazione.

Per un ripristino completo, preferisci `initialSnapshot`:

```jsx
<FormRenderer
  schema={schema}
  initialSnapshot={{
    raw_values: saved.raw_values,
    repeatable: saved.repeatable,
    timestamps: saved.timestamps,
  }}
  onSnapshotChange={(snapshot, change) => {
    if (change.dirty) queueDraft(snapshot)
  }}
  onSubmit={saveRecord}
/>
```

Uno snapshot iniziale sostituisce `initialValues` per i valori grezzi dei campi. Ripristina anche le
voci ripetibili annidate e i timestamp di client e server come un unico stato coerente.

## Osservare le bozze

`onSnapshotChange(snapshot, change)` viene chiamato prima con `{ kind: "seed", dirty: false }`. Le
modifiche successive dell'utente usano `{ kind: "change", dirty: boolean }`.

Lo snapshot contiene:

```js
{
  raw_values: {},
  repeatable: {},
  timestamps: {
    created_at_client: null,
    updated_at_client: null,
    created_at_server: null,
    updated_at_server: null,
  },
}
```

## Inviare i record

`onSubmit(record, meta)` riceve il record strutturato descritto in
[Output e record](/it/core/output-records). `meta` contiene `rawValues`, `repeatable`, `timestamps`
e `validationSummary`.

Se `onSubmit` restituisce una promise, un overlay configurato con `autoCloseOverlayOnSubmit` si
chiude solo dopo la risoluzione della promise. In caso di rifiuto resta aperto. Usa
`submitBlockedReason` per i requisiti dell'applicazione esterni allo schema e `externalDirty` per lo
stato dell'applicazione esterno al renderer.
