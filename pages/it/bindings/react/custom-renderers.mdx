I renderer personalizzati cambiano la presentazione senza spostare fuori da `form0-core` calcoli,
visibilità, obbligatorietà o validazione.

## Override circoscritti

Preferisci `FieldRegistryProvider` quando un'applicazione, una route, un test o una story di
Storybook richiede un insieme di renderer isolato:

```jsx
import { FieldRegistryProvider, FormRenderer } from "form0-react"
import { DateField } from "./date-field.jsx"

export function AppForm({ schema }) {
  return (
    <FieldRegistryProvider renderers={{ DateField }}>
      <FormRenderer schema={schema} />
    </FieldRegistryProvider>
  )
}
```

Un renderer riceve lo stesso contratto di campo usato dai renderer predefiniti:

```jsx
function DateField({ field, value, onChange, readOnly, inputProps, className }) {
  return (
    <input
      {...inputProps}
      className={className}
      type="date"
      value={value ?? ""}
      disabled={readOnly}
      onChange={(event) => onChange(event.target.value)}
    />
  )
}
```

Mantieni le proprietà di accessibilità fornite in `inputProps`.

## Istanze del registro e override globali

Usa `createFieldRegistry({ includeDefaults, renderers })` per un'istanza esplicita del registro. Le
funzioni di modulo `registerFieldComponent`, `unregisterFieldComponent` e `resetFieldComponents`
modificano il registro predefinito condiviso: è meglio riservarle all'avvio dell'applicazione o ai
test.

Si possono registrare solo i tipi di campo dichiarati da `form0-core`. Un nuovo tipo di campo dello
schema deve essere prima definito nel nucleo; un renderer React da solo non può estendere il
contratto dello schema.
