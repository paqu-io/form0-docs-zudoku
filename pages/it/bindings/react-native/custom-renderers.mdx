I renderer personalizzati cambiano la presentazione nativa senza spostare fuori da `form0-core` i
calcoli, la visibilità, l'obbligatorietà o la validazione.

## Override per singolo modulo

Passa una mappa di renderer direttamente a `FormRenderer` per un modulo isolato:

```jsx
import { FormRenderer } from "form0-react-native"
import { PhotoField } from "./photo-field.jsx"

;<FormRenderer schema={schema} renderers={{ PhotoField }} />
```

Un renderer riceve il campo e il suo stato di interazione valutato:

```jsx
function PhotoField({ field, value, onChange, readOnly, required, error, inputProps }) {
  // Render application-owned capture, preview, and removal controls.
}
```

Mantieni le proprietà applicabili di `inputProps` e chiama `onChange` con la forma del valore
prevista dallo schema e dall'invio.

## Provider, registri e override globali

Usa `FieldRegistryProvider` per un override limitato a un sottoalbero oppure
`createFieldRegistry({ includeDefaults, renderers })` per un'istanza di registro esplicita. Le
funzioni di modulo `registerFieldComponent`, `unregisterFieldComponent` e `resetFieldComponents`
modificano il registro predefinito condiviso: riservale al codice di bootstrap o ai test.

Si possono registrare solo i tipi di campo dichiarati da `form0-core`. Un nuovo tipo di campo deve
essere prima definito nel nucleo; un renderer nativo da solo non può estendere il contratto dello
schema.
