Gli eventi sono definiti in `form.events.code` e valutati durante l'esecuzione. Usa `ON` per
registrare i gestori e `SETVALUE`/`ALERT` per interagire con il modulo.

Quando il motore viene creato, `events.code` viene eseguito una volta per registrare i gestori. Questo
non attiva alcun evento. Un evento viene eseguito solo quando la tua applicazione chiama `engine.trigger(...)` o
quando un binding lo attiva in risposta a un'interazione dell'utente o a una transizione del ciclo di
vita dell'applicazione.

## Esempio rapido

```js
ON("change", "age", function (event) {
  if ($age >= 18) {
    // can_vote is a TextField in this example
    SETVALUE("can_vote", "yes")
  }
})
```

## Attivazione degli eventi nei binding ufficiali

Per impostazione predefinita, `FormRenderer` in `form0-react` e `form0-react-native` attiva questi
eventi:

| Evento            | Quando viene eseguito                                                     |
| ----------------- | ------------------------------------------------------------------------- |
| `load-record`     | Ogni volta che si apre un record, in modifica o in sola lettura           |
| `new-record`      | Un nuovo record entra in modifica                                         |
| `edit-record`     | Un record esistente entra in modifica                                     |
| `change`          | Un utente modifica un campo, oppure aggiunge, modifica o rimuove una riga |
| `focus`, `blur`   | Un campo di testo o numerico riceve o perde il focus                      |
| `validate-record` | Un utente invia il modulo o salva una bozza                               |
| `save-record`     | Dopo la validazione, una volta per ogni tentativo di salvataggio          |
| `cancel-record`   | Un utente conferma l'annullamento di un record                            |
| `unload-record`   | Un record si chiude                                                       |
| `change-status`   | Un utente cambia il campo di stato, se è attivo                           |

Le righe hanno eventi propri: `load-repeatable`, `new-repeatable`, `edit-repeatable`,
`validate-repeatable`, `save-repeatable`, `cancel-repeatable`, `unload-repeatable`. Una riga non
esegue mai gli eventi del record principale.

I campi di scelta segnalano le modifiche con `change`, non con `focus` o `blur`. `click` è
disponibile, ma nessun controllo integrato lo emette, quindi attivalo tu. I valori predefiniti, i
calcoli e `SETVALUE` non attivano `change`.

Usa `engineOptions.events` per cambiare questo comportamento. `lifecycle: false` mantiene solo
`load-record`, `edit-record` e `change` per i campi del record principale. `fieldInteractions: []`
disattiva `focus` e `blur`.

Se usi direttamente `form0-core`, nulla viene attivato per te. Chiama
`engine.trigger(eventType, fieldKey, metadata)` nel punto giusto della tua applicazione. Registrare
un gestore con `ON` non fa eseguire il suo evento.

- [`ON`](/it/core/builtins/events/on)

- [`ALERT`](/it/core/builtins/events/alert)

Per la registrazione, l'ordine di esecuzione, l'ambito dei gestori e la gestione delle operazioni,
vedi [Eventi e operazioni](/it/core/engine/events-operations).

I gestori di eventi possono usare anche i builtin di espressione condivisi elencati in
[Calcoli ed espressioni](/it/core/builtins/calculations-expressions-overview). I builtin riservati ai
calcoli, come `SETRESULT`, non sono disponibili nei gestori di eventi.
