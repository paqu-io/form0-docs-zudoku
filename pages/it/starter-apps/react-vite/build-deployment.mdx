Crea una build di produzione e visualizzala in anteprima in locale:

```bash
npm run build
npm run preview
```

Vite scrive l'output statico in `dist`. Pubblica quella directory su un hosting statico o servila
dietro il server della tua applicazione.

## Requisiti di hosting

Lo starter usa il routing lato browser. Configura l'hosting in modo che serva `index.html` come
fallback per le route dell'applicazione come `/contact/standard`; altrimenti la navigazione diretta a
quegli URL può restituire la pagina 404 dell'hosting.

Il proxy predefinito verso i connettori esiste solo nel server di sviluppo. In produzione l'invio
deve passare da un endpoint server gestito dall'applicazione. Configura quell'endpoint in modo
esplicito, invece di presumere che il proxy `/api` di sviluppo sia presente dopo il deployment.

## Prima del deployment

- Esegui `npm run lint` e `npm run build`.
- Controlla l'avviso sulla dimensione del bundle generato e introduci il code splitting quando la crescita dell'applicazione rende eccessivo il download iniziale.
- Tieni i file `.env` locali fuori dal controllo di versione.
- Verifica che nessun segreto sia incorporato negli asset generati.
- Prova la navigazione diretta a ogni route pubblica dell'applicazione.
- Leggi la [policy di sicurezza](https://github.com/paqu-io/form0-web-tmpl-react-vite/blob/main/SECURITY.md).

I valori d'ambiente di Vite destinati al codice del browser vengono incorporati staticamente in fase
di build. Trattali come configurazione pubblica, anche quando provengono da un file d'ambiente
locale.
