## Un percorso del modulo dice che il modulo non è stato trovato

Confermare che l'identificatore URL corrisponda esattamente a una voce in `src/forms/registry.js`.
che la sua importazione dinamica punta a un file schema esistente.

## Una schema non riesce a caricare

Aprire la console del browser per l'errore di importazione, quindi eseguire la convalida schema tramite form0-cli.
Gli errori di sintassi e i percorsi di importazione relativi errati sono le cause più comuni.

```bash
form0
```

Caricare schema ed eseguire `validate`. Vedere [Validare e visualizzare in anteprima](/it/cli/schemas/validate-preview).

## Una renderer personalizzata non viene utilizzata

Controlla tutti e tre i nomi: il tipo di campo schema, la sua mappatura in `form0.config.js` e il resolver
identificatore in `src/field-renderers/resolver.js`. Il resolver registra un avviso per gli identificatori sconosciuti.

## I contributi non possono raggiungere il server CLI

Eseguire `form0 serve --app` dalla directory del progetto. Se il server CLI utilizza un indirizzo diverso, impostare
`FORM0_DEV_API_URL` prima di iniziare Vite o nel relativo file `.env` locale.
`devServer.apiBaseUrl` corrisponde ancora al percorso proxy Vite.

## La valutazione dei lavoratori fallisce

Imposta temporaneamente `engine.mode` su `main-thread` per isolare il caricamento di worker dal comportamento di schema.
controllare la console del browser, i percorsi delle risorse e il tipo di contenuto di distribuzione.
[Operatori e prestazioni](/it/bindings/react/workers-performance).

## I link diretti ritornano 404 dopo la distribuzione

Configurare l'host statico per tornare a `index.html` per percorsi di applicazione sconosciuti.
problema di configurazione, non un problema di definizione del percorso React.

Per errori di rendering a livello di pacchetto, continuare con
[React risoluzione dei problemi](/it/bindings/react/troubleshooting). Per errori di database, utilizzare
[Connettore risoluzione dei problemi](/it/connectors/troubleshooting).
