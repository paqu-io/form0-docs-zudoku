`Form0Form` fornisce un gestore submission predefinito quando il chiamante non fornisce `onSubmit`.
handler crea o accetta un record form0 strutturato e lo registra per lo sviluppo.

Quando `devServer.submitToConnector` è `true`, chiama anche due endpoint locali:

1. `POST /api/create-record` quando renderer non ha già prodotto un record strutturato completo.
2. `POST /api/submit-record` per inviare tale record ai connettori gestiti da form0-cli.

Il proxy Vite inoltra `/api` al server di sviluppo CLI. Avviare entrambi i processi con:

```bash
form0 serve --app
```

## Applicazione del rifornimento comportamento submission

Passa da `onSubmit` a `Form0Form` per sostituire il gestore predefinito.
`useDefaultSubmitHandler={false}` se il modulo deve essere visualizzato senza il percorso submission.

Per il contratto completo di record di callback e metadati, vedere
[Valori, snapshots e submission](/it/bindings/react/values-snapshots-submission).

> [Attenzione]
> Gli endpoint CLI e il proxy Vite sono aiutanti di sviluppo locale, non una produzione submission API.
> Un'applicazione distribuita ha bisogno di un limite di server attendibile con autenticazione, autorizzazione,
> convalida, limitazione della velocità e controlli di archiviazione appropriati.
> codice del browser.

Utilizzare solo schemas da autori attendibili. Espressioni di schema eseguire all'interno del documentato
[form0-core trust border](/it/core/security).
