## Expo segnala dipendenze incompatibili

Usa i comandi di Expo che tengono conto della compatibilità invece di installare versioni arbitrarie
dei pacchetti nativi:

```bash
npx expo install --check
npx expo-doctor@latest
```

Usa `npx expo install --fix` solo dopo aver esaminato le modifiche proposte. Tratta un
aggiornamento dell'SDK di Expo come una migrazione e segui la guida all'aggiornamento dell'SDK.

## Un dispositivo non riesce ad aprire il progetto

Verifica che il dispositivo possa raggiungere il computer di sviluppo tramite la LAN. Controlla
firewall, VPN, isolamento dei client Wi-Fi, porta configurata e se il client si aspetta Expo Go o una
development build. Se usi un URL pubblico, verifica che non restituisca una pagina interstiziale
prima degli endpoint di Expo. Expo Go supporta una sola versione dell'SDK alla volta e la
distribuzione compatibile varia a seconda della piattaforma. Crea una nuova development build dopo
aver cambiato l'SDK di Expo o le dipendenze native.

## Manca un'immagine di supporto

Verifica che il percorso corrisponda a quello dello schema, inserisci gli asset inclusi nel bundle in
`assets/supporting-images` ed esegui `npm run generate-images`. Esegui il commit del registro
rigenerato e riavvia Metro quando il grafo dei moduli non è aggiornato.

## I font o i moduli nativi non si caricano

Attendi `useFonts(form0Fonts)` prima del rendering. Installa i pacchetti Expo con `npx expo install`
e usa una development build per i moduli nativi non disponibili in Expo Go.

## Le scritture in SQLite non riescono

Valida `databaseName` e `tableName`, esamina i log del dispositivo e attiva temporaneamente l'output
di debug dell'archiviazione. I nomi delle tabelle accettano solo lettere, cifre e underscore; i
valori non validi tornano al valore predefinito. Ricorda che cancellare i dati dell'app elimina il
database nella sandbox.

Per gli errori specifici dei componenti, prosegui con
[Risoluzione dei problemi di React Native](/it/bindings/react-native/troubleshooting).
