---
title: Scegliere un connettore
description: Confronta i connettori ufficiali PostgreSQL e SQLite.
---

<PageBadges />

Entrambi i connettori ufficiali accettano la stessa forma di record strutturato di form0 e
conservano le relazioni delle sezioni ripetibili annidate. Scegli in base a dove viene eseguita
l'applicazione e a come devono essere gestiti i suoi dati.

| Aspetto       | PostgreSQL                                                   | SQLite                                                    |
| ------------- | ------------------------------------------------------------ | --------------------------------------------------------- |
| Archiviazione | Database di rete                                             | File di database locale                                   |
| Uso ideale    | Applicazioni server e deployment condivisi                   | Strumenti locali e deployment Node.js semplici            |
| Concorrenza   | Pool di connessioni e concorrenza gestita dal database       | Vincoli del locking dei file di SQLite                    |
| Operatività   | Ruoli del database, TLS, backup e amministrazione del server | Permessi dei file, copie, backup e conservazione dei dati |
| Contenuto     | JSONB più colonne proiettate                                 | Testo JSON più colonne proiettate                         |
| Piattaforma   | Node.js con accesso a PostgreSQL                             | Node.js con una build nativa supportata                   |

Usa PostgreSQL quando più processi o deployment condividono gli invii, oppure quando contano le query
e i controlli operativi a livello di database. Usa SQLite quando i dati devono restare in un file
locale e l'applicazione può funzionare entro il modello di concorrenza di SQLite.

Il connettore SQLite per Node.js non è compatibile con React Native né con Expo. Le applicazioni
mobile devono usare un'archiviazione nativa della piattaforma, come `expo-sqlite`, e definire un
proprio livello di sincronizzazione.
