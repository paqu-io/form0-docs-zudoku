## Catalogue des fournisseurs

form0 utilise le catalogue de fournisseurs et de modèles de Pi sans renommer les fournisseurs ni
modifier leurs capacités d’authentification. Le catalogue peut évoluer avec la version figée de la
dépendance Pi ; consultez la version installée plutôt qu’une liste statique.

```ansi
form0(ai)> /providers
form0(ai)> /models <provider>
```

La base de la préversion, testée manuellement, couvre :

- OpenAI avec une clé d’API
- OpenAI Codex avec l’OAuth d’un abonnement
- Anthropic avec une clé d’API ou l’OAuth d’un abonnement Claude
- Google Gemini avec une clé d’API
- OpenRouter avec une clé d’API ou OAuth
- Les modèles locaux Ollama

D’autres fournisseurs exposés par Pi peuvent fonctionner, mais ils ne font pas partie de la base
vérifiée manuellement.

## Authentification

Utilisez le type d’authentification indiqué par le catalogue des fournisseurs :

```ansi
form0(ai)> /login <provider> <api_key|oauth>
```

Selon le fournisseur, OAuth peut proposer un flux dans le navigateur ou par code d’appareil. Les
clés d’API sont saisies dans une invite masquée. Les identifiants fournis par des variables
d’environnement reconnues par Pi restent disponibles.

L’accès à l’API OpenAI et un abonnement ChatGPT/Codex sont deux voies d’authentification distinctes.
Utilisez le fournisseur OpenAI pour une clé d’API et le fournisseur OpenAI Codex pour l’OAuth
d’abonnement.

L’authentification ne choisit pas de modèle automatiquement. Après la connexion, listez les modèles
et sélectionnez-en un explicitement :

```ansi
form0(ai)> /models openai-codex
form0(ai)> /model openai-codex/gpt-5.6-luna
```

## Sélection et persistance du modèle

Le modèle sélectionné est enregistré dans la conversation Pi associée au chemin canonique du schéma.
Quitter le mode IA puis revenir au même schéma restaure cette sélection. Elle n’est enregistrée ni
dans le schéma ni dans la configuration du projet.

Utilisez `/model` sans argument ou `/status` pour consulter la sélection courante. `/new` et
`/clear` démarrent une nouvelle conversation en conservant le modèle actif. Si le modèle enregistré
n’existe plus ou que son authentification n’est pas disponible, la CLI affiche l’avertissement de
repli de Pi.

## Stockage local

Les identifiants, les données du catalogue de modèles et les conversations sont stockés sous
`~/.form0-cli/ai/`. Les répertoires sont réservés à l’utilisateur courant, et les fichiers
d’identifiants et de sessions ont des permissions limitées à cet utilisateur. Les conversations
enregistrées peuvent contenir le schéma complet.

Rien n’est écrit dans un schéma form0 tant qu’une proposition approuvée n’est pas appliquée. Les
identifiants des fournisseurs et les choix de modèle ne sont jamais ajoutés à la configuration du
projet.

## Modèles locaux et cloud

La découverte Ollama interroge le service local et expose via Pi les modèles trouvés. Les modèles
locaux restent disponibles lorsque la politique du schéma bloque les fournisseurs cloud. La
sélection d’un modèle cloud est refusée si le formulaire ou un champ définit `allowCloud: false` ;
voir [Confidentialité et sécurité](/fr/cli/ai-authoring/privacy-security).
