Utilisez `form0 run <schema> --values <input>` pour évaluer un formulaire. L’entrée peut être une
valeur JSON en ligne ou le chemin d’un fichier JSON, YAML ou YML.

La commande affiche l’état évalué du moteur : valeurs, erreurs de validation, visibilité, caractère
obligatoire et lecture seule. Les champs d’entrée inconnus sont ignorés avec un avertissement.

Il s’agit de valeurs initiales, et non d’appels aux setters. Pour des champs nommés `country` (SingleChoice) et `countries` (MultiChoice), le JSON suivant utilise leurs formes abrégées distinctes. Les formes prises en charge sont normalisées au chargement ; les valeurs chargées mal formées restent disponibles pour la validation. Consultez [la mise à jour et la normalisation des valeurs](/fr/core/engine/value-updates) pour les représentations en mémoire et soumises ainsi que le contrat plus strict des setters.

```json
{ "country": "it", "countries": ["it", "fr"] }
```

## Diagnostics de calcul

Les diagnostics d’exécution identifient le champ, le code stable, la gravité, la phase et une
correction éventuelle. Les détails vont sur stderr ; l’état évalué reste sur stdout.

La commande affiche l’état même si un calcul échoue, puis se termine avec le code `1` si
l’évaluation contient un diagnostic de gravité erreur. Les avertissements seuls donnent le code
`0`. Un échec dans une passe intermédiaire reste inclus, même si une passe ultérieure réussit.

Ajoutez `--no-diagnostics` pour masquer les détails. La collecte et le code de sortie restent
actifs. Les diagnostics sont distincts des erreurs de champ dans `state.errors` ; ils ne changent
pas la validation de soumission. Consultez les
[diagnostics de calcul](/fr/core/engine/calculations-dependencies#voir-les-erreurs-et-les-avertissements).
