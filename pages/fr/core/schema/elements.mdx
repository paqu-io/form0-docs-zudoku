`form.elements` est un tableau ordonné de champs et de conteneurs. Les conteneurs peuvent imbriquer
d'autres champs grâce à leur propre tableau `elements`.

## Clés et noms de données

- `data_name` : identifiant lisible utilisé comme clé de la valeur dans l'état du moteur (unique ; uniquement minuscules a-z, 0-9 et tiret bas ; 42 caractères maximum)
- `key` : identifiant interne, généralement dérivé de `data_name` (unique, hexadécimal, 8 caractères)

Pour faire référence à des champs dans des conditions ou dans `title_field.elements`, vous pouvez utiliser `key` ou `data_name`. Lorsque vous écrivez un schéma à la main, `data_name` est souvent plus pratique, car plus facile à retenir.

## Conteneurs

Les types de champs suivants peuvent contenir des éléments imbriqués :

- `Section` – regroupe visuellement les champs
- `RepeatableSection` – permet plusieurs instances de ses enfants

`BuildingPlanSection` accepte aussi des éléments imbriqués, mais a un comportement spécifique pour générer des formulaires dynamiques. Voir [BuildingPlanSection](/fr/core/fields/containers#buildingplansection) pour plus de détails.

## Exemple

```json
{
  "type": "Section",
  "key": "personal_section",
  "data_name": "personal_section",
  "label": "Personal info",
  "display": "inline",
  "description": null,
  "description_mode": null,
  "visible": true,
  "visible_conditions": null,
  "elements": [
    {
      "type": "TextField",
      "key": "first_name",
      "data_name": "first_name",
      "label": "First name",
      "display": "default",
      "description": null,
      "description_mode": null,
      "required": true,
      "required_conditions": null,
      "visible": true,
      "visible_conditions": null,
      "read_only": false,
      "read_only_conditions": null,
      "default_value": null,
      "pattern": null,
      "pattern_description": null,
      "supporting_image": false,
      "supporting_image_path": null,
      "supporting_image_display": null
    }
  ]
}
```
