Les conditions sont utilisées dans `visible_conditions`, `required_conditions` et `read_only_conditions`.
Elles font référence à d'autres champs et s'évaluent à vrai ou faux.

## Structure d'une condition

```json
{
  "field_id": "age",
  "operator": "greater_or_equal_than",
  "value": 18
}
```

Vous pouvez combiner des conditions avec `and` ou `or` :

```json
{
  "and": [
    { "field_id": "country", "operator": "equal_to", "value": "us" },
    { "field_id": "age", "operator": "greater_or_equal_than", "value": 18 }
  ]
}
```

## Opérateurs

| Opérateur               | Signification                    |
| ----------------------- | -------------------------------- |
| `equal_to`              | Égal à la valeur fournie         |
| `not_equal_to`          | Différent de la valeur           |
| `greater_than`          | Supérieur à la valeur            |
| `less_than`             | Inférieur à la valeur            |
| `greater_or_equal_than` | Supérieur ou égal à              |
| `less_or_equal_than`    | inférieur ou égal à              |
| `contains`              | Le tableau contient la valeur    |
| `starts_with`           | La chaîne commence par la valeur |
| `is_empty`              | La valeur est vide ou null       |
| `is_not_empty`          | La valeur n'est pas vide         |

### Opérateurs pris en charge par type de champ

Les opérateurs sont validés en fonction du type de champ référencé. Par exemple :

- Les champs de texte prennent en charge `contains` et `starts_with`
- Les champs numériques et de date prennent en charge les opérateurs de comparaison
- Les champs de choix prennent en charge `equal_to` et `contains` (choix multiple)

Les conditions de choix comparent les valeurs des réponses, et non l'objet conteneur du renderer :

- `SingleChoiceField` et `BooleanField` comparent le `value` du choix sélectionné.
- `MultiChoiceField` utilise un tableau de valeurs sélectionnées. `contains` vérifie une valeur,
  tandis que `equal_to` vérifie la sélection complète sans dépendre de l'ordre.
- Une réponse personnalisée « other » non vide intervient via son `value` ou son libellé, afin que
  les opérateurs de vide reflètent ce que l'utilisateur a saisi.

Si un opérateur n'est pas valide pour le champ référencé, la validation échoue.

## Références aux champs

`field_id` doit pointer vers la `key` du champ. `data_name` est accepté en solution de repli, mais `key` est
recommandé, car il ne change jamais quand les libellés changent.
