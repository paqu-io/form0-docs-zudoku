Les événements sont définis dans `form.events.code` et évalués à l'exécution. Utilisez `ON` pour
enregistrer des gestionnaires et `SETVALUE`/`ALERT` pour interagir avec le formulaire.

Lors de la création du moteur, `events.code` s'exécute une fois afin d'enregistrer les gestionnaires.
Cela ne déclenche aucun événement. Un événement s'exécute uniquement lorsque votre application appelle
`engine.trigger(...)` ou lorsqu'un binding le déclenche en réponse à une interaction utilisateur ou
à une transition du cycle de vie de l'application.

## Exemple rapide

```js
ON("change", "age", function (event) {
  if ($age >= 18) {
    // can_vote is a TextField in this example
    SETVALUE("can_vote", "yes")
  }
})
```

## Déclenchement des événements dans les bindings officiels

Par défaut, `FormRenderer` dans `form0-react` et `form0-react-native` déclenche ces événements :

| Événement         | Quand il s’exécute                                                            |
| ----------------- | ----------------------------------------------------------------------------- |
| `load-record`     | Chaque fois qu’un enregistrement s’ouvre, en modification ou en lecture seule |
| `new-record`      | Un nouvel enregistrement passe en modification                                |
| `edit-record`     | Un enregistrement existant passe en modification                              |
| `change`          | Un utilisateur modifie un champ, ou ajoute, modifie ou supprime une ligne     |
| `focus`, `blur`   | Un champ texte ou numérique gagne ou perd le focus                            |
| `validate-record` | Un utilisateur soumet le formulaire ou sauvegarde un brouillon                |
| `save-record`     | Après la validation, une fois par tentative de sauvegarde                     |
| `cancel-record`   | Un utilisateur confirme l’annulation d’un enregistrement                      |
| `unload-record`   | Un enregistrement se ferme                                                    |
| `change-status`   | Un utilisateur modifie le champ de statut, s’il est activé                    |

Les lignes ont leurs propres événements : `load-repeatable`, `new-repeatable`, `edit-repeatable`,
`validate-repeatable`, `save-repeatable`, `cancel-repeatable`, `unload-repeatable`. Une ligne
n’exécute jamais les événements de l’enregistrement principal.

Les champs de choix signalent les changements avec `change`, pas avec `focus` ou `blur`. `click` est
disponible, mais aucun contrôle intégré ne l’émet : déclenchez-le donc vous-même. Les valeurs par
défaut, les calculs et `SETVALUE` ne déclenchent pas `change`.

Utilisez `engineOptions.events` pour modifier ce comportement. `lifecycle: false` ne garde que
`load-record`, `edit-record` et `change` pour les champs de l’enregistrement principal.
`fieldInteractions: []` désactive `focus` et `blur`.

Si vous utilisez `form0-core` directement, rien n’est déclenché à votre place. Appelez
`engine.trigger(eventType, fieldKey, metadata)` au bon moment dans votre application. Enregistrer un
gestionnaire avec `ON` ne fait pas s’exécuter son événement.

## Builtins d'événement

### <Badge variant="secondary">Événements</Badge>

- [`ON`](/fr/core/builtins/events/on)
- [`OFF`](/fr/core/builtins/events/off)
- [`ALERT`](/fr/core/builtins/events/alert)
- [`SETVALUE`](/fr/core/builtins/events/setvalue)

Pour l'enregistrement, l'ordre d'exécution, la portée des gestionnaires et le traitement des
opérations, voir [Événements et opérations](/fr/core/engine/events-operations).

Les gestionnaires d'événements peuvent aussi utiliser les builtins d'expression partagés listés dans
[Calculs et expressions](/fr/core/builtins/calculations-expressions-overview). Les builtins réservés
aux calculs, comme `SETRESULT`, ne sont pas disponibles dans les gestionnaires d'événements.
