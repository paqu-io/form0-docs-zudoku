form0-core expose deux sorties principales :

- État du moteur (`values`, `errors`, `visible`, `required`, `read_only`)
- Enregistrements structurés pour la persistance (`createStructuredRecord`)

## État du moteur

Après `engine.eval()`, appelez `engine.getState()` pour accéder au dernier état.

## Enregistrements structurés

`createStructuredRecord` transforme l'état du moteur dans un format adapté à la soumission :

- `form_values` utilise les clés de champ par défaut
- Les sections répétables deviennent des tableaux d'enregistrements enfants
- Les sections sont omises (ce ne sont que des conteneurs)

### Mode des clés de champ

Vous pouvez utiliser les clés `data_name` à la place grâce à `fieldKeyMode` :

```js
const record = createStructuredRecord(state, fields, {
  fieldKeyMode: "data-name",
})
```

## Sections répétables

### Sérialisation coopérative

Pour un grand enregistrement évalué, `createStructuredRecordAsync` utilise la même transformation
et rend le contrôle à l'environnement entre les lignes. Gardez l'état, les champs et les options
stables jusqu'à la fin ; les contrôleurs de soumission des bindings possèdent déjà l'instantané choisi.

```js
const abortController = new AbortController()
const record = await createStructuredRecordAsync(
  snapshot,
  fields,
  {
    originalElements: schema.form.elements,
    mainRecordId: 0,
  },
  {
    signal: abortController.signal,
    budgetMs: 8,
    yieldToHost,
  },
)
```

Le quatrième argument contrôle la planification et reste hors de l'enregistrement. `yieldToHost`
est une fonction facultative renvoyant une promesse pour une tâche de l'environnement ; sans elle,
core utilise un temporisateur. L'annulation rejette la promesse avec `AbortError` sans renvoyer
d'enregistrement partiel. Cette méthode n'effectue ni calcul, ni validation, ni persistance. Elle
conserve la structure du sérialiseur synchrone, l'ID zéro, l'ordre des lignes, le format des médias,
les titres et les règles d'horodatage. Les formateurs de champs restent synchrones.

Les sections répétables créent des enregistrements imbriqués. Utilisez `originalElements` pour conserver
la bonne structure d'imbrication lors de la création des enregistrements.

Les entrées abrégées ne modifient ni les valeurs par défaut ni les formats soumis. SingleChoice/Boolean utilise choice_value et other_value ; MultiChoice utilise choices_value et other_value. [Voir le contrat de mise à jour des valeurs](/fr/core/engine/value-updates).

## Charger un enregistrement stocké

Utilisez `buildFormRecordSnapshot(schema, record)` pour reconvertir un enregistrement stocké en
valeurs exploitables par form0, par exemple pour le rouvrir. La fonction renvoie `raw_values`,
`repeatable` et `timestamps`, la même forme que `initialSnapshot`.

```jsx
import { buildFormRecordSnapshot } from "form0-core"
import { FormRenderer } from "form0-react"

export function SavedCase({ schema, savedRecord }) {
  const snapshot = buildFormRecordSnapshot(schema, savedRecord)

  return (
    <FormRenderer
      engineOptions={{ events: { recordKind: "existing" } }}
      schema={schema}
      initialSnapshot={snapshot}
    />
  )
}
```

Elle lève une erreur si un champ a une forme incorrecte, comme un champ de choix stocké en texte
simple. Pour vérifier un enregistrement stocké par rapport au schéma, passez `raw_values` et
`repeatable` à `createRecordEvaluator().prepareSubmission()`.

## Lignes vides enregistrées

Une ligne répétable enregistrée explicitement reste dans l’enregistrement même si toutes ses réponses sont vides. Par exemple, un article de commande accepté avec TextField `product` et NumericField `quantity` facultatifs est sérialisé avec les deux réponses à `null`, en conservant son identifiant et ses horodatages. Cela s’applique aux lignes imbriquées et aux deux sérialiseurs structurés, indépendamment de la conservation des valeurs masquées ou d’un gestionnaire de récupération. Annulez une ligne non enregistrée ou supprimez une ligne enregistrée pour l’exclure. Les collections vides restent vides ; la sérialisation ne crée pas de lignes.
