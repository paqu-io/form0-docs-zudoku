Le starter est une application Vite classique. Ses valeurs par défaut propres à form0 se trouvent
dans `form0.config.js`, tandis que le code de l’application reste dans `src`.

```text
.
├── form0.config.js
├── src/
│   ├── components/        # application form wrappers and UI primitives
│   ├── field-renderers/   # application-owned renderer overrides
│   ├── forms/             # schema files, registry, and loader
│   ├── pages/             # home and form routes
│   ├── styles/            # application-level form overrides
│   └── themes/            # optional Vanilla Extract themes
└── vite.config.js         # React plugins, aliases, and local API proxy
```

## Zones de configuration

Modifiez `form0.config.js` pour contrôler :

- `layout` : la largeur par défaut, le placement des libellés et la mise en page de chaque présentation ;
- `engine` : l’évaluation sur le thread principal ou dans un worker et la stratégie de store React ;
- `theme` : clair, sombre, système ou une classe de thème de l’application ;
- `interaction` : le comportement initial en édition ou en lecture seule et la soumission dans les overlays ;
- `schemas.directory` : le répertoire des schémas utilisé par l’outillage ;
- `devServer` : la commande et le port de l’application, l’option de soumission aux connecteurs et l’URL de base de l’API ;
- `fieldRenderers` : les types de champs remplacés par des renderers de l’application ;
- `output.useKeys` : si les enregistrements structurés privilégient les clés du schéma ou les noms de données.

Les propriétés des composants peuvent surcharger les valeurs par défaut concernées pour un
formulaire donné. Gardez les valeurs par défaut réutilisables de l’application dans la configuration
et le comportement du formulaire dans le schéma.

> [!CAUTION]
> Laissez le store du moteur sur `snapshot` dans ce starter. La configuration incluse documente une
> limitation connue des messages de validation avec le mode `selector`.

## Proxy de développement

Par défaut, le serveur Vite redirige `/api` vers `http://localhost:3030`. Définissez
`FORM0_DEV_API_URL` dans l’environnement du processus ou dans un fichier `.env` local de Vite pour
utiliser une autre adresse de serveur de la CLI. Cette valeur est lue par la configuration de Vite et
n’est pas exposée au code du navigateur.

Vite écoute sur le port 5173 avec `strictPort`, conformément à `devServer.port`. Dans form0-cli
0.7.0 et les versions ultérieures, lorsque le port est déclaré, `form0 serve --app` démarre d’abord
l’application, démarre le serveur de la CLI dès que ce port accepte les connexions, puis affiche
l’URL de l’application à ouvrir. Si le port 5173 est occupé, Vite s’arrête au lieu de choisir un
autre port. Pour utiliser un autre port, modifiez-le à la fois dans `vite.config.js` et dans
`devServer.port`.

Ne placez pas d’identifiants dans des variables côté client. Les identifiants de base de données
relèvent de l’environnement de la CLI ou du connecteur côté serveur, décrit dans la
[documentation des connecteurs](/fr/connectors/overview).
