## Une route de formulaire indique que le formulaire n'a pas été trouvé

Confirmez que l'identifiant URL correspond exactement à une entrée dans `src/forms/registry.js`.
que son importation dynamique pointe vers un fichier schema existant.

## Un schema ne se charge pas

Ouvrez la console du navigateur pour l'erreur d'importation, puis exécutez schema Validation par form0-cli . JSON
Les erreurs de syntaxe et les chemins d'importation relatifs incorrects sont les causes les plus courantes.

```bash
form0
```

Charger le schema et courir `validate` . Voir [Valider et prévisualiser](/cli/schemas/validate-preview) .

## Un renderer personnalisé n'est pas utilisé

Vérifiez les trois noms: le type de champ schema, son mappage dans `form0.config.js` et le résolveur
identifiant dans `src/field-renderers/resolver.js`. Le résolveur enregistre un avertissement pour les identifiants inconnus.

## Les envois ne peuvent pas atteindre le serveur CLI

Exécuter `form0 serve --app` dans le répertoire du projet. Si la CLI serveur utilise une adresse différente,
`FORM0_DEV_API_URL` avant de démarrer Vite ou dans le fichier `.env` local correspondant.
`devServer.apiBaseUrl` correspond toujours au chemin du proxy Vite.

## L’évaluation des travailleurs échoue

Définissez temporairement `engine.mode` à `main-thread` pour isoler le chargement worker du comportement schema.
Vérifiez la console du navigateur, les chemins d’accès aux ressources et le type de contenu de déploiement.
[Travailleurs et performance](/fr/bindings/react/workers-performance).

## La page 404 est retournée après le déploiement

Configurez l'hôte statique pour revenir à `index.html` pour les chemins d'application inconnus. Ceci est un hôte
problème de configuration, pas un problème de définition de route React.

Pour les échecs de rendu au niveau du package, continuez avec
[React dépannage](/fr/bindings/react/troubleshooting). Pour les échecs de base de données, utilisez
[Dépannage du connecteur](/fr/connectors/troubleshooting).
