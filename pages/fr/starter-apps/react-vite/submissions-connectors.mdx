`Form0Form` fournit un gestionnaire submission par défaut lorsque l'appelant ne fournit pas `onSubmit`.
handler crée ou accepte un enregistrement form0 structuré et l'enregistre pour le développement.

Lorsque `devServer.submitToConnector` est `true`, il appelle également deux points de terminaison locaux:

1. `POST /api/create-record` lorsque le renderer n'a pas encore produit un enregistrement structuré complet.
2. `POST /api/submit-record` pour envoyer cet enregistrement aux connecteurs gérés par form0-cli.

Le proxy Vite transmet `/api` au serveur de développement CLI. Démarrez les deux processus avec:

```bash
form0 serve --app
```

## Comportement de l'application d'approvisionnement submission

Passez `onSubmit` à `Form0Form` pour remplacer le gestionnaire par défaut.
`useDefaultSubmitHandler={false}` si le formulaire doit être rendu sans chemin submission.

Pour le contrat complet d'enregistrement de rappel et de métadonnées, voir
[Valeurs, snapshots et submission](/fr/bindings/react/values-snapshots-submission).

> [! AVERTISSEMENT]
> Les points de terminaison CLI et le proxy Vite sont des aides au développement local, pas un submission de production.
> Une application déployée a besoin d'une limite de serveur de confiance avec authentification, autorisation,
> des contrôles de validation, de limitation de débit et de stockage appropriés.
> code du navigateur.

N'utilisez schemas qu'à partir d'auteurs approuvés.
