## Expo signale des dépendances incompatibles

Utilisez les commandes d’Expo qui tiennent compte de la compatibilité au lieu d’installer des
versions arbitraires de paquets natifs :

```bash
npx expo install --check
npx expo-doctor@latest
```

Utilisez `npx expo install --fix` seulement après avoir examiné les changements proposés. Traitez
une mise à niveau du SDK Expo comme une migration et suivez son guide de mise à niveau.

## L’appareil n’ouvre pas le projet

Vérifiez que l’appareil peut atteindre la machine de développement par LAN. Contrôlez les pare-feu,
les VPN, l’isolation des clients Wi-Fi, le port configuré et si le client attend Expo Go ou un
development build. Avec une URL publique, vérifiez qu’elle ne renvoie aucune page intermédiaire
avant les endpoints Expo.
Expo Go ne prend en charge qu’une ligne de SDK à la fois et sa distribution compatible varie selon
la plateforme. Créez un nouveau development build après tout changement du SDK Expo ou des
dépendances natives.

## Une image auxiliaire est absente

Vérifiez que son chemin correspond au schéma, placez les ressources incluses dans
`assets/supporting-images`, puis exécutez `npm run generate-images`. Validez le registre régénéré et
redémarrez Metro si le graphe de modules est obsolète.

## Les polices ou modules natifs ne se chargent pas

Attendez `useFonts(form0Fonts)` avant le rendu. Installez les paquets Expo avec `npx expo install` et
utilisez un development build pour les modules natifs indisponibles dans Expo Go.

## Échec SQLite

Vérifiez `databaseName` et `tableName`, consultez les journaux de l’appareil, puis activez
temporairement la sortie de débogage du stockage. Les noms de table n’acceptent que les lettres, les
chiffres et les underscores ; les valeurs invalides utilisent la valeur par défaut. Effacer les
données de l’application supprime la base du sandbox.

Consultez aussi la [résolution des problèmes React Native](/fr/bindings/react-native/troubleshooting).
