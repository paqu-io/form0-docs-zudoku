form0 est un moteur open source pour les formulaires pilotés par un schéma. Il évalue les calculs,
les conditions, la validation et les événements, tout en vous laissant maîtres de la présentation,
du stockage et de l'architecture backend. Les projets ci-dessous répondent à des problèmes voisins,
à des niveaux différents : des bibliothèques de formulaires intégrables jusqu'aux plateformes
complètes de collecte de données.

<Callout type="info" title="Dernière vérification : 29 septembre 2026">
  Les autres projets évoluent. Chaque affirmation sur un autre projet s'appuie sur sa propre
  documentation, listée dans la section Sources en bas de page. Si une information n'est plus à
  jour, utilisez "Edit this page" pour proposer une correction.
</Callout>

<Callout type="note" title="Comment lire la comparaison">
  "Intégré" signifie que la fonctionnalité fait partie du schéma ou de l'environnement d'exécution
  du projet, sans code applicatif supplémentaire. ODK est une plateforme de collecte de données et
  non une bibliothèque JavaScript intégrable ; certaines comparaisons portent donc sur un autre
  niveau de l'architecture.
</Callout>

### Logique des formulaires

| Projet            | Calculs et conditions                                                                                | Données répétées                                                                          | Modèle de réaction                                                                                     |
| ----------------- | ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| **form0**         | Expressions JavaScript pour les calculs, la visibilité, le caractère obligatoire et la lecture seule | Logique limitée à la ligne ; l'agrégation entre lignes n'est pas intégrée pour l'instant  | Les gestionnaires `ON` renvoient des opérations que le host applique                                   |
| **SurveyJS**      | Expressions et valeurs calculées SurveyJS                                                            | Panneaux dynamiques et matrices, avec des fonctions d'agrégation comme `sumInArray()`     | Les expressions et les déclencheurs peuvent modifier le modèle du questionnaire                        |
| **Form.io**       | Calculs, conditions et logique de composant en JavaScript ou en JSON Logic                           | Data Grid et Edit Grid ; le code de calcul personnalisé peut lire les données de la ligne | Des déclencheurs de logique exécutent des actions sur des composants ou des valeurs                    |
| **ODK (XLSForm)** | Calculs, pertinence, contraintes et caractère obligatoire exprimés en XPath                          | Répétitions avec des fonctions XPath comme `sum()`                                        | Les valeurs référencées peuvent déclencher un nouveau calcul                                           |
| **JSON Forms**    | Validation JSON Schema et règles de UI schema ; les calculs nécessitent du code applicatif           | Tableaux JSON Schema ; l'agrégation avancée nécessite du code applicatif                  | Les règles d'interface réagissent de façon déclarative ; `onChange` signale les changements de données |
| **RJSF**          | Conditions JSON Schema et UI schema dynamique ; les calculs nécessitent du code applicatif           | Tableaux JSON Schema ; l'agrégation avancée nécessite du code applicatif                  | Callbacks `onChange` gérés par l'application                                                           |

## Ce qui distingue form0

### Le même moteur logique pour le web et le mobile natif

Les bindings React et React Native évaluent tous deux la logique du formulaire avec `form0-core`.
Une définition de formulaire n'a pas besoin d'un second système de calculs ou de conditions quand une
application passe du web au mobile natif, et React Native affiche des contrôles natifs plutôt
qu'une vue web. La présentation et le cycle de vie propre à chaque binding peuvent néanmoins
différer d'un environnement à l'autre.

Parmi les projets ci-dessus, ODK propose aussi un environnement d'exécution natif pour Android, mais
dans le cadre de sa plateforme de collecte et non comme une bibliothèque React Native pour votre
application.

### Le comportement du formulaire est indépendant de votre stack

form0 prend en charge ce qu'est un formulaire et la façon dont il se comporte. Votre application
garde la maîtrise de son design system, de la navigation, de l'authentification, de l'API, du
stockage, du processus de soumission et de l'hébergement. Le moteur convient donc aux produits sur
mesure qui ont besoin d'un comportement de formulaire élaboré sans adopter une plateforme de
formulaires hébergée.

### Les événements décrivent les changements au lieu de modifier l'état implicitement

Un gestionnaire d'événements form0 renvoie des opérations comme `SETVALUE` ou `ALERT` ; il ne
modifie pas directement l'état du formulaire. Un host sans interface peut décider comment appliquer
ces opérations, tandis que les bindings officiels appliquent celles qu'ils prennent en charge. Le
moteur rejette tout `SETVALUE` hors de la portée du gestionnaire, et l'application d'une opération
ne déclenche pas de nouvel événement `change`, ce qui évite les boucles entre gestionnaires. Voir
[Événements et opérations](/fr/core/engine/events-operations).

À l'inverse, les déclencheurs de SurveyJS et les actions de logique de Form.io modifient directement
leurs modèles de formulaire.

### Des références de champ simples, résolues selon la portée

Dans form0, une expression lit tout champ auquel elle a accès avec `$data_name`, que ce champ se
trouve dans le formulaire principal ou dans la même ligne répétée. Le moteur résout la référence
selon l'endroit où l'expression est définie. SurveyJS utilise des préfixes comme `{panel.question}`
et `{parentPanel.question}` dans les panneaux dynamiques, Form.io distingue `data` de `row`, et
XLSForm utilise des chemins XPath. Voir [Portées parent et enfant](/fr/core/engine/parent-child-scopes).

### Des calculs ordonnés par dépendance, avec diagnostic des cycles

À la création du moteur, form0 détermine de quels champs dépend chaque champ calculé et les évalue
dans cet ordre. Si des champs calculés dépendent les uns des autres en boucle, le moteur leur
attribue `null`, émet un diagnostic qui nomme le cycle et continue d'évaluer les champs
indépendants. Voir [Calculs et dépendances](/fr/core/engine/calculations-dependencies).

### Des expressions JavaScript avec des contrôles de validation

Les expressions form0 utilisent la syntaxe JavaScript : inutile d'apprendre un langage
d'expressions à part. `SAFE` et `CUSTOM` fournissent des contrôles de validation et de
configuration, mais ce ne sont pas des bacs à sable de sécurité. Les schémas contenant des
expressions ou des scripts d'événements doivent provenir d'auteurs de confiance, et les applications
doivent [isoler l'exécution](/fr/core/security) lorsque les schémas ne sont pas fiables. Form.io
prend aussi en charge JavaScript et un évaluateur protégé, tandis que SurveyJS et XLSForm utilisent
leurs propres langages d'expressions.

### Un environnement d'exécution ouvert et des outils pour les développeurs

Le moteur, les bindings React et React Native, la CLI avec création assistée par IA et les
connecteurs de stockage sont sous licence MIT. Vous pouvez créer, prévisualiser et exécuter des
formulaires sans dépendre d'un environnement d'exécution commercial.

## Quand un autre projet peut mieux convenir

- **Vous avez besoin dès aujourd'hui d'agrégations entre lignes répétées définies dans le schéma.**
  SurveyJS et ODK proposent des fonctions d'agrégation documentées. Form.io permet d'implémenter
  l'agrégation avec du code de calcul personnalisé. form0 ne propose pas encore d'agrégation entre
  lignes intégrée.
- **Vous voulez un outil de création visuelle fourni avec la bibliothèque.** Form.io inclut un
  éditeur visuel open source, et SurveyJS propose Survey Creator sous licence commerciale. form0
  s'appuie pour l'instant sur des schémas JSON et sur la création assistée par la CLI.
  [reform](https://reformapp.io) est une plateforme hébergée de collecte de données, distincte et
  construite sur form0, qui inclut la création visuelle de formulaires.
- **Vous avez besoin d'une plateforme éprouvée de collecte hors ligne.** ODK et les outils basés sur
  XLSForm offrent une collecte mature sur Android et une création à partir de tableurs. form0 fournit
  le moteur et le binding natif ; le stockage hors ligne, la synchronisation et les opérations
  backend restent à la charge de votre application.
- **Votre application utilise déjà JSON Schema comme modèle de formulaire.** JSON Forms et RJSF
  génèrent des formulaires directement à partir de JSON Schema et peuvent demander moins de
  conversion vers un schéma de formulaire distinct.
