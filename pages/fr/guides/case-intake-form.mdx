Dans ce guide, vous créez un formulaire d’ouverture de dossier de support et vous l’exécutez dans le
starter React et Vite. Le formulaire comprend :

- des champs de contact qui apparaissent, et deviennent obligatoires, selon le mode de contact
  préféré ;
- une priorité calculée à partir des réponses ;
- une date de réponse calculée à partir de la priorité ;
- un champ d’impact métier obligatoire uniquement pour les dossiers de priorité haute.

Tout ce comportement tient dans un seul schéma JSON. Le code de l’application se contente
d’enregistrer le formulaire.

**Durée :** environ 15 minutes.

## Avant de commencer

- **Node.js** `22.19.0+`
- **form0-cli**, installé avec `npm install --global form0-cli`

Le starter React + Vite inclut les paquets form0 nécessaires. Si vous utilisez une application
existante, suivez [Installer et afficher avec React](/fr/bindings/react/install-render) pour installer
ou mettre à jour ses paquets form0 avant de copier le schéma.

## Comment ça marche

### Champs conditionnels

Le champ **Email** est masqué par défaut. Ses conditions l’affichent, et le rendent obligatoire,
lorsque le mode de contact est `email` :

```json
{
  "data_name": "email",
  "visible": false,
  "visible_conditions": {
    "field_id": "contact_method",
    "operator": "equal_to",
    "value": "email"
  },
  "required_conditions": {
    "field_id": "contact_method",
    "operator": "equal_to",
    "value": "email"
  }
}
```

Une condition sur un champ de choix compare la `value` du choix sélectionné, pas son libellé.
Consultez [Conditions et opérateurs](/fr/core/schema/conditions-operators).

Masquer un champ n’efface pas sa valeur. Si quelqu’un saisit une adresse e-mail puis passe à
**Phone**, l’adresse reste dans les valeurs du formulaire. C’est à votre application de décider si
les valeurs masquées doivent être conservées.

### Priorité calculée

`priority` est un `CalculatedField`. Son expression `calculate` lit les réponses à **Who is
affected?** et **Is work blocked?** :

```js
IF(
  !CHOICEVALUE($impact),
  null,
  IF(
    CHOICEVALUE($blocked) === "yes" || CHOICEVALUE($impact) === "organization",
    "high",
    IF(CHOICEVALUE($impact) === "team", "normal", "low"),
  ),
)
```

`CHOICEVALUE()` renvoie la valeur sélectionnée d’un champ de choix. Le premier `IF()` laisse la
priorité vide tant que **Who is affected?** n’a pas de réponse.

Les expressions de cette page sont réparties sur plusieurs lignes pour rester lisibles. Dans le
schéma, chacune tient sur une seule ligne. Si vous écrivez un calcul sur plusieurs lignes, indiquez
son résultat avec [`SETRESULT()`](/fr/core/builtins/calculations-expressions/setresult) ou une
instruction `return` explicite.

### Date de réponse

`respond_by` ajoute un nombre de jours à `received_on`, selon la priorité :

```js
DATEADD(
  $received_on,
  IF($priority === "high", 1, IF($priority === "normal", 3, IF($priority === "low", 7, null))),
)
```

[`DATEADD()`](/fr/core/builtins/calculations-expressions/dateadd) renvoie `null` lorsque le nombre
de jours est vide : la date reste vide tant qu’il n’y a pas de priorité.
`"display": { "style": "date" }` indique au renderer d’afficher le résultat comme une date.

### Une condition pilotée par un calcul

**Describe the business impact** utilise le même type de condition que **Email**, mais il lit
`priority`, qui est lui-même calculé :

```json
{
  "data_name": "business_impact",
  "visible": false,
  "visible_conditions": {
    "field_id": "priority",
    "operator": "equal_to",
    "value": "high"
  },
  "required_conditions": {
    "field_id": "priority",
    "operator": "equal_to",
    "value": "high"
  }
}
```

Cela fonctionne parce que le moteur exécute les calculs avant d’évaluer les conditions.

## Ce qui vient de se passer

À chaque réponse modifiée, le renderer du starter l’a transmise au moteur form0. Le moteur a
recalculé `priority` puis `respond_by`, dans l’ordre des dépendances, puis il a réévalué quels champs
sont visibles et obligatoires. Le renderer s’est contenté d’afficher le résultat. Le même schéma
produit le même comportement dans toute application qui utilise form0.
