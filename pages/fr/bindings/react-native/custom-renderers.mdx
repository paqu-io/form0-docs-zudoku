Les renderers personnalisés modifient la présentation native sans sortir de `form0-core` les
calculs, la visibilité, le caractère obligatoire ni la validation.

## Surcharges par formulaire

Transmettez une table de renderers directement à `FormRenderer` pour un formulaire isolé :

```jsx
import { FormRenderer } from "form0-react-native"
import { PhotoField } from "./photo-field.jsx"

;<FormRenderer schema={schema} renderers={{ PhotoField }} />
```

Un renderer reçoit le champ et son état d’interaction évalué :

```jsx
function PhotoField({ field, value, onChange, readOnly, required, error, inputProps }) {
  // Render application-owned capture, preview, and removal controls.
}
```

Conservez les propriétés applicables de `inputProps` et appelez `onChange` avec la forme de valeur
attendue par le schéma et la soumission.

## Fournisseurs, registres et surcharges globales

Utilisez `FieldRegistryProvider` pour une surcharge limitée à un sous-arbre ou
`createFieldRegistry({ includeDefaults, renderers })` pour une instance de registre explicite. Les
fonctions de module `registerFieldComponent`, `unregisterFieldComponent` et `resetFieldComponents`
modifient le registre par défaut partagé ; réservez-les au code d’amorçage ou aux tests.

Seuls les types de champs déclarés par `form0-core` peuvent être enregistrés. Un nouveau type de
champ doit d’abord être défini dans le noyau ; un renderer natif ne suffit pas à étendre le contrat
du schéma.
