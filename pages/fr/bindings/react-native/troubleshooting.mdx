## Metro ne peut pas résoudre une dépendance de pair

Installez les versions compatibles `lucide-react-native` et `react-native-svg`. Dans Expo, utilisez
`npx expo install react-native-svg react-native-safe-area-context expo-font` donc le natif installé
paquets correspondent au SDK actif, puis redémarrez Metro.

## Le texte utilise une police de secours

Chargez `form0Fonts` avec `expo-font` avant de rendre le formulaire.
thème, garder ses jetons font-family alignés avec les noms chargés dans le registre de polices natif.

## Une image de soutien locale est manquante

Les actifs locaux ne peuvent pas être résolus de manière arbitraire runtime chaînes. Fournissez `imageResolver` avec a
path-to-source map statique, régénérez la carte si le starter la possède, et redémarrez Metro après avoir ajouté
de nouveaux actifs.

## Un champ indique qu'il n'est pas pris en charge ou provisoire

Cochez [Champ intégré renderers](/fr/bindings/react-native/built-in-renderers). `PhotoField`,
`VideoField`, et `FormLinkField` ont besoin de remplacements d'application pour le comportement de production.
override est passé au même `FormRenderer` ou fournisseur de registre qui rend le formulaire.

## La soumission ne fonctionne pas

`onSubmit` est validé. Confirmez que le formulaire est en mode d'édition, fournissez un gestionnaire d'envoi et utilisez
la feuille de navigation de validation pour inspecter les erreurs. Pour drafts tolérant à la validation, fournissez `onSave`
et définissez `primaryActionMode="save"`.

## Les brouillons disparaissent après le redémarrage

Les snapshots sont émis mais jamais stockés par le binding. Persistez-les via `onSnapshotChange` ou
`onSave`, et restaurer l'objet complet avec `initialSnapshot`. Ne le remplacez pas par
valeurs de champ brutes lorsque les entrées reproductibles ou les horodatages sont importants.
