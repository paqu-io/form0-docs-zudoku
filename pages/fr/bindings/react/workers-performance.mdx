## Exécution du moteur

La valeur par défaut, `engineMode="main-thread"`, évalue le moteur du formulaire sur le thread de
l’interface. Utilisez `engineMode="worker"` pour déplacer l’évaluation du moteur dans le module
worker fourni avec le paquet lorsque les Web Workers sont disponibles :

```jsx
<FormRenderer schema={schema} engineMode="worker" />
```

Vite prend en charge le modèle de module worker statique utilisé par le paquet et génère le worker
lors du build de production. Le starter Vite maintenu exclut `form0-react` de l’optimisation des
dépendances afin que ce worker reste disponible.

L’API publique de `FormRenderer` n’accepte ni URL de worker personnalisée ni fabrique de workers.
Les applications qui utilisent un autre bundler doivent vérifier qu’il prend en charge
`new Worker(new URL("./worker.js", import.meta.url), { type: "module" })` ; sinon, utilisez le mode
par défaut sur le thread principal.

Si le navigateur ne prend pas en charge les Workers, le binding revient à une exécution sur le
thread principal.

## Mode de stockage React

`engineStoreMode="snapshot"` clone le snapshot du moteur dans l’état React ; c’est la valeur par
défaut. `engineStoreMode="selector"` utilise des abonnements par champ pour limiter les nouveaux
rendus globaux.

Considérez le mode selector comme une optimisation : avant de l’adopter, vérifiez dans l’application
cible les erreurs des champs, les résumés de navigation, les sections répétables et le comportement
de la soumission.
