## Mode d’interaction

Définissez `mode="edit"` ou `mode="readonly"`. Les formulaires en lecture seule peuvent proposer un
bouton de passage en édition avec `allowReadOnlyEditToggle` ; utilisez
`readOnlyEditToggleDisabledReason` lorsque l’application host doit expliquer pourquoi l’édition
n’est pas disponible.

`showPrimaryActionsInViewMode` détermine si les actions principales désactivées restent visibles en
mode consultation.

## Emplacement

`formPlacement` accepte :

- `form-page` pour le contenu normal d’une page ;
- `form-modal` pour un affichage dans une modale ;
- `form-spotlight` pour un affichage dans un panneau latéral ou en mode spotlight.

Pour les overlays, fournissez `onRequestClose`. `autoCloseOverlayOnSubmit` ferme l’overlay après une
soumission synchrone réussie ou une fois la promesse de soumission renvoyée résolue. La confirmation
d’abandon tient compte des modifications du renderer et de `externalDirty`.

## Mise en page et navigation

- `labelPosition` accepte `top` ou `side`.
- `labelWidthPercent` contrôle la colonne des libellés dans la mise en page latérale.
- `formWidth` accepte une valeur de largeur CSS.
- `forceShowNavigationPanel` garde la navigation par sections visible alors qu’elle serait normalement réduite.
- `simplifiedMode` présente un champ à la fois ; `onSimplifiedNavigation` observe la progression.

Les sections, les entrées répétables, la navigation vers les erreurs de validation, la gestion du
focus et les actions au clavier sont gérées par `FormRenderer`. Gardez le comportement conditionnel
dans le schéma plutôt que de le dupliquer dans l’état React.
