## La forme n'est pas stylisée

Importez `form0-react/index.css` une fois dans le point d'entrée de l'application.
Importation CSS à partir de dépendances.

## Un champ indique qu'il n'est pas supporté

Confirmez que le type est répertorié dans le [Catalogue de champs de base](/fr/core/fields/catalog).
connu mais intentionnellement remplacé, vérifiez que le composant est enregistré dans le même
`FieldRegistryProvider` sous-arbre comme `FormRenderer`.

## Le schema échoue pendant le rendu

`FormRenderer` valide `schema.form` et nécessite `form.elements`. Utilisation
[`form0 validate`](/fr/cli/schemas/validate-preview) avant de charger le schema dans l'application.

## Le mode travailleur ne peut pas charger le worker

Premier retour à `engineMode="main-thread"`. Pour Vite, garder le constructeur worker statiquement
analysable et exclure `form0-react` de l'optimisation des dépendances comme indiqué dans le web maintenu
Les autres bundlers doivent supporter le module ESM workers basé sur `new URL(..., import.meta.url)`.

Les options personnalisées `workerUrl` et `createWorker` ne font pas partie du `FormRenderer` API public.

## Les mises à jour n'apparaissent pas pendant le développement des paquets locaux

Reconstruire `form0-react`, redémarrer le serveur de développement consommateur, et effacer uniquement les paquets
si nécessaire. Vite peut conserver une copie optimisée d'une
package installé.

## La soumission ne fonctionne pas

Vérifiez que `onSubmit` est une fonction, que le formulaire est en mode édition, que `submitBlockedReason` est vide, et
le résumé de validation ne contient pas d'erreurs. Pour les superpositions renvoyant une promesse,
L'application peut présenter l'échec tant que l'overlay reste ouvert.
