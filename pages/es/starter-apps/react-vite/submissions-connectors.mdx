`Form0Form` proporciona un manejador de envío predeterminado cuando quien lo usa no pasa `onSubmit`.
El manejador crea o recibe un registro estructurado de form0 y lo escribe en la consola como ayuda
durante el desarrollo.

Cuando `devServer.submitToConnector` es `true`, también llama a dos endpoints locales:

1. `POST /api/create-record` cuando el renderer todavía no ha generado un registro estructurado completo.
2. `POST /api/submit-record` para enviar ese registro a los conectores que gestiona form0-cli.

El proxy de Vite redirige `/api` al servidor de desarrollo de la CLI. Inicia ambos procesos con:

```bash
form0 serve --app
```

Usa la [gestión de conectores de la CLI](/es/cli/connector-management) para instalar, configurar,
probar y consultar un conector. Consulta [Elegir un conector](/es/connectors/choose) para comparar
PostgreSQL y SQLite.

## Proporciona el comportamiento de envío de la aplicación

Pasa `onSubmit` a `Form0Form` para sustituir el manejador predeterminado. Establece
`useDefaultSubmitHandler={false}` si el formulario debe renderizarse sin ninguna de las dos vías de
envío.

Para el contrato completo del registro y los metadatos que recibe la callback, consulta
[Valores, snapshots y envío](/es/bindings/react/values-snapshots-submission).

> [!WARNING]
> Los endpoints de la CLI y el proxy de Vite son herramientas de desarrollo local, no una API de
> envío para producción. Una aplicación desplegada necesita un servidor de confianza con
> autenticación, autorización, validación, limitación de peticiones y controles de almacenamiento
> adecuados. Nunca incluyas credenciales de bases de datos en el código del navegador.

Usa solo esquemas de autores de confianza. Las expresiones del esquema se ejecutan dentro del
[límite de confianza de form0-core](/es/core/security) documentado.
