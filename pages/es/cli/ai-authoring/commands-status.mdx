## Referencia de comandos

El modo IA acepta peticiones en lenguaje natural y comandos con barra. El texto sin prefijo siempre
se envía al modelo; todos los comandos deterministas empiezan por `/`. Por ejemplo, usa `/preview`,
no `preview`.

| Comando                        | Finalidad                                                                                          |
| ------------------------------ | -------------------------------------------------------------------------------------------------- |
| `/help`                        | Muestra el resumen alineado de los comandos de IA.                                                 |
| `/status`                      | Muestra el esquema, el borrador, el modelo, la autenticación, la política, la actividad y la cola. |
| `/providers`                   | Lista los proveedores de Pi, sus métodos de autenticación y el número de modelos.                  |
| `/models <provider>`           | Lista los identificadores de modelo de un proveedor.                                               |
| `/login <provider> <method>`   | Autentica con el flujo `api_key` u `oauth` definido por Pi.                                        |
| `/model [provider/model]`      | Abre el selector de modelos o selecciona un proveedor y un modelo concretos.                       |
| `/privacy`                     | Explica la política efectiva de nube y consentimiento del esquema.                                 |
| `/load [file\|form]`           | Carga otro formulario y cambia a su conversación propia del esquema.                               |
| `/preview`                     | Muestra el árbol legible del formulario del esquema de trabajo.                                    |
| `/json`                        | Muestra el esquema de trabajo en JSON sin formato.                                                 |
| `/validate`                    | Valida el esquema de trabajo, incluida una propuesta sin aplicar.                                  |
| `/serve [options]`             | Inicia el servidor de vista previa; `--app` inicia también la aplicación configurada.              |
| `/serve status`, `/serve stop` | Consulta o detiene los servidores de vista previa sin salir del modo IA.                           |
| `/diff`                        | Muestra los cambios acumulados desde que entraste en el modo IA.                                   |
| `/diff --pending`              | Muestra solo los cambios entre la última aplicación y la propuesta pendiente.                      |
| `/apply [schema-path]`         | Vuelve a comprobar y guarda de forma atómica la propuesta pendiente.                               |
| `/discard`                     | Abandona el borrador y restaura la vista previa del esquema guardado en el navegador.              |
| `/undo`                        | Prepara el último esquema guardado en esta sesión para aprobarlo explícitamente.                   |
| `/new`                         | Inicia una conversación nueva y conserva el modelo seleccionado.                                   |
| `/clear`                       | Elimina el historial guardado de este formulario y empieza de nuevo con el modelo seleccionado.    |
| `/cancel`                      | Interrumpe la petición activa y vacía la cola de peticiones pendientes.                            |
| `/exit`                        | Vuelve a la shell; pide confirmación si hay una propuesta sin aplicar.                             |

## Estado

El estado es local: no contacta con ningún proveedor ni consulta saldos de créditos:

```ansi
form0(ai)> /status

AI authoring status
  Schema:             /project/form.schema.json
  Draft:              none
  Provider:           openai-codex
  Model:              gpt-5.6-luna
  Cloud policy:       allowed
  Conversation:       persisted
  Activity:           idle
  Queued follow-ups:  0
  Authentication:
    openai-codex  oauth (stored, subscription) [selected]
```

La salida de autenticación indica el origen y el tipo, pero nunca muestra una credencial. Un
proveedor puede estar autenticado sin estar seleccionado, y estar autenticado no implica tener
créditos disponibles.

## Prompts de listo y ocupado

Una petición cambia el estado del prompt y muestra el modelo activo:

```ansi
[AI] Thinking with openai-codex/gpt-5.6-luna…
form0(ai,busy)>
```

Con el servidor de vista previa en ejecución, el prompt es `form0(server,ai,busy)>`. Al terminar el
procesamiento, vuelve a `form0(ai)>` o `form0(server,ai)>`.

Pulsar Intro en una línea vacía no hace nada salvo volver a mostrar el prompt actual. El texto en
lenguaje natural que se introduce mientras la CLI está ocupada se pone en cola en orden FIFO, y la
CLI confirma su posición en la cola.

## Comandos disponibles mientras está ocupado

Mientras hay una petición activa al proveedor, siguen disponibles `/help`, `/status`, `/privacy`,
`/cancel`, `/serve status` y `/serve stop`. Los demás comandos con barra se rechazan hasta que
termina el procesamiento, para que el modelo, la conversación o el borrador no cambien mientras la
petición está en curso.

La cancelación pide a Pi que interrumpa la petición actual y vacía la cola de peticiones pendientes.
Una cancelación correcta vuelve al prompt de listo sin mostrar la interrupción del proveedor como un
segundo error.
