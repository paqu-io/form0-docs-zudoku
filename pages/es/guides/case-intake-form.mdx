En esta guía, creas un formulario de registro de casos de soporte y lo ejecutas en el starter de
React y Vite. El formulario tiene:

- campos de contacto que aparecen, y pasan a ser obligatorios, según el método de contacto preferido;
- una prioridad calculada a partir de las respuestas;
- una fecha de respuesta calculada a partir de la prioridad; y
- un campo de impacto en el negocio que solo es obligatorio en los casos de prioridad alta.

Todo este comportamiento vive en un único esquema JSON. El código de la aplicación solo registra el
formulario.

**Tiempo:** unos 15 minutos.

## Antes de empezar

- **Node.js** `22.19.0+`
- **form0-cli**, instalado con `npm install --global form0-cli`

El starter de React + Vite incluye los paquetes form0 necesarios. Si usas una aplicación existente,
necesita como mínimo `form0-core` 0.4.1 y `form0-react` 0.2.2. Sigue
[Instalar y renderizar con React](/es/bindings/react/install-render) para instalarlos o
actualizarlos antes de copiar el esquema.

## Cómo funciona

### Campos condicionales

El campo **Email** está oculto por defecto. Sus condiciones lo muestran, y lo hacen obligatorio,
cuando el método de contacto es `email`:

```json
{
  "data_name": "email",
  "visible": false,
  "visible_conditions": {
    "field_id": "contact_method",
    "operator": "equal_to",
    "value": "email"
  },
  "required_conditions": {
    "field_id": "contact_method",
    "operator": "equal_to",
    "value": "email"
  }
}
```

Una condición sobre un campo de selección compara el `value` de la opción elegida, no su etiqueta.
Consulta [Condiciones y operadores](/es/core/schema/conditions-operators).

Ocultar un campo no borra su valor. Si alguien escribe una dirección de email y luego cambia a
**Phone**, la dirección sigue en los valores del formulario. Decide en tu aplicación si los valores
ocultos deben conservarse.

### Prioridad calculada

`priority` es un `CalculatedField`. Su expresión `calculate` lee las respuestas a **Who is
affected?** y **Is work blocked?**:

```js
IF(
  !CHOICEVALUE($impact),
  null,
  IF(
    CHOICEVALUE($blocked) === "yes" || CHOICEVALUE($impact) === "organization",
    "high",
    IF(CHOICEVALUE($impact) === "team", "normal", "low"),
  ),
)
```

`CHOICEVALUE()` devuelve el valor elegido en un campo de selección. El primer `IF()` deja la
prioridad vacía hasta que **Who is affected?** tiene respuesta.

Las expresiones de esta página se dividen en varias líneas para que se lean mejor. En el esquema,
cada una ocupa una sola línea. Si escribes un cálculo de varias líneas, indica su resultado con
[`SETRESULT()`](/es/core/builtins/calculations-expressions/setresult) o una sentencia `return` explícita.

### Fecha de respuesta

`respond_by` suma un número de días a `received_on`, según la prioridad:

```js
DATEADD(
  $received_on,
  IF($priority === "high", 1, IF($priority === "normal", 3, IF($priority === "low", 7, null))),
)
```

[`DATEADD()`](/es/core/builtins/calculations-expressions/dateadd) devuelve `null` cuando el número
de días está vacío, así que la fecha queda vacía hasta que hay una prioridad.
`"display": { "style": "date" }` indica al renderer que muestre el resultado como fecha.

### Una condición que depende de un cálculo

**Describe the business impact** usa el mismo tipo de condición que **Email**, pero lee `priority`,
que también es un valor calculado:

```json
{
  "data_name": "business_impact",
  "visible": false,
  "visible_conditions": {
    "field_id": "priority",
    "operator": "equal_to",
    "value": "high"
  },
  "required_conditions": {
    "field_id": "priority",
    "operator": "equal_to",
    "value": "high"
  }
}
```

Funciona porque el motor ejecuta los cálculos antes de evaluar las condiciones.

## Qué acaba de pasar

Cada vez que cambiaste una respuesta, el renderer del starter la pasó al motor de form0. El motor
volvió a calcular `priority` y después `respond_by`, en orden de dependencias, y luego volvió a
evaluar qué campos son visibles y obligatorios. El renderer solo mostró el resultado. El mismo
esquema produce el mismo comportamiento en cualquier aplicación que use form0.

  qué orden.
- [Cálculos y dependencias](/es/core/engine/calculations-dependencies): cómo ordena el motor los
  cálculos que dependen unos de otros.

  enviado en el starter y cómo mandarlo a una base de datos.
