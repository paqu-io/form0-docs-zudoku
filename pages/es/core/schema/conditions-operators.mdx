Las condiciones se utilizan en `visible_conditions`, `required_conditions` y `read_only_conditions`.
Hacen referencia a otros campos y se evalúan como verdaderas o falsas.

## Forma de la condición

```json
{
  "field_id": "age",
  "operator": "greater_or_equal_than",
  "value": 18
}
```

Puedes combinar condiciones con `and` u `or`:

```json
{
  "and": [
    { "field_id": "country", "operator": "equal_to", "value": "us" },
    { "field_id": "age", "operator": "greater_or_equal_than", "value": 18 }
  ]
}
```

## Operadores

| Operador                | Significado                     |
| ----------------------- | ------------------------------- |
| `equal_to`              | Es igual al valor proporcionado |
| `not_equal_to`          | No es igual al valor            |
| `greater_than`          | Mayor que el valor              |
| `less_than`             | Menor que el valor              |
| `greater_or_equal_than` | Mayor o igual que               |
| `less_or_equal_than`    | Menor o igual que               |
| `contains`              | El array contiene el valor      |
| `starts_with`           | La cadena comienza con el valor |
| `is_empty`              | El valor está vacío o es nulo   |
| `is_not_empty`          | El valor no está vacío          |

### Operadores admitidos por tipo de campo

Los operadores se validan contra el tipo de campo referenciado. Por ejemplo:

- Los campos de texto admiten `contains` y `starts_with`
- Los campos numéricos/de fecha admiten operadores de comparación
- Los campos de selección admiten `equal_to` y `contains` (selección múltiple)

Las condiciones de selección comparan los valores de respuesta, no el objeto contenedor del renderer:

- `SingleChoiceField` y `BooleanField` comparan el `value` de la opción seleccionada.
- `MultiChoiceField` usa un array de valores seleccionados. `contains` comprueba un valor, mientras
  que `equal_to` comprueba la selección completa sin depender del orden.
- Una respuesta personalizada “other” no vacía participa mediante su `value` o etiqueta, por lo que
  los operadores de vacío reflejan lo que introdujo el usuario.

Si un operador no es válido para el campo referenciado, la validación falla.

## Referencias de campo

`field_id` debe apuntar a la `key` del campo. También se acepta `data_name` como alternativa, pero se
recomienda `key` porque no cambia nunca cuando cambian las etiquetas.
