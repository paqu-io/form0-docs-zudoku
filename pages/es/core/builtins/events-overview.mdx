Los eventos se definen en `form.events.code` y se evalúan durante la ejecución. Usa `ON` para
registrar manejadores y `SETVALUE`/`ALERT` para interactuar con el formulario.

Al crear el motor, `events.code` se ejecuta una vez para registrar los manejadores. Esto no dispara
ningún evento. Un evento solo se ejecuta cuando tu aplicación llama a `engine.trigger(...)` o cuando un
binding lo dispara por una interacción del usuario o una transición del ciclo de vida de la aplicación.

## Ejemplo rápido

```js
ON("change", "age", function (event) {
  if ($age >= 18) {
    // can_vote is a TextField in this example
    SETVALUE("can_vote", "yes")
  }
})
```

## Despacho de eventos en los bindings oficiales

De forma predeterminada, `FormRenderer` en `form0-react` y `form0-react-native` despacha estos
eventos:

| Evento            | Cuándo se ejecuta                                                 |
| ----------------- | ----------------------------------------------------------------- |
| `load-record`     | Cada vez que se abre un registro, para editarlo o en solo lectura |
| `new-record`      | Un registro nuevo empieza a editarse                              |
| `edit-record`     | Un registro existente empieza a editarse                          |
| `change`          | Un usuario edita un campo, o añade, edita o elimina una fila      |
| `focus`, `blur`   | Un campo de texto o numérico recibe o pierde el foco              |
| `validate-record` | Un usuario envía el formulario o guarda un borrador               |
| `save-record`     | Después de la validación, una vez por cada intento de guardado    |
| `cancel-record`   | Un usuario confirma la cancelación de un registro                 |
| `unload-record`   | Un registro se cierra                                             |
| `change-status`   | Un usuario cambia el campo de estado, si está activado            |

Las filas tienen sus propios eventos: `load-repeatable`, `new-repeatable`, `edit-repeatable`,
`validate-repeatable`, `save-repeatable`, `cancel-repeatable`, `unload-repeatable`. Una fila nunca
ejecuta los eventos del registro principal.

Los campos de opción informan de los cambios con `change`, no con `focus` ni `blur`. `click` está
disponible, pero ningún control integrado lo emite, así que despáchalo tú. Los valores
predeterminados, los cálculos y `SETVALUE` no despachan `change`.

Usa `engineOptions.events` para cambiar esto. `lifecycle: false` deja solo `load-record`,
`edit-record` y `change` para los campos del registro principal. `fieldInteractions: []` desactiva
`focus` y `blur`.

Si usas `form0-core` directamente, nada se despacha por ti. Llama a
`engine.trigger(eventType, fieldKey, metadata)` en el punto adecuado de tu aplicación. Registrar un
manejador con `ON` no hace que su evento se ejecute.

## Builtins de eventos

### <Badge variant="secondary">Eventos</Badge>

- [`ON`](/es/core/builtins/events/on)
- [`OFF`](/es/core/builtins/events/off)
- [`ALERT`](/es/core/builtins/events/alert)
- [`SETVALUE`](/es/core/builtins/events/setvalue)
- [`INVALID`](/es/core/builtins/events/invalid)

Para el registro, el orden de ejecución, el ámbito de los manejadores y la gestión de operaciones,
consulta [Eventos y operaciones](/es/core/engine/events-operations).

Los manejadores de eventos también pueden usar los builtins de expresión compartidos que se indican en
[Cálculos y expresiones](/es/core/builtins/calculations-expressions-overview). Los builtins
exclusivos de los cálculos, como `SETRESULT`, no están disponibles en los manejadores de eventos.
