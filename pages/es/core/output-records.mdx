form0-core expone dos salidas principales:

- Estado del motor (`values`, `errors`, `visible`, `required`, `read_only`)
- Registros estructurados para persistencia (`createStructuredRecord`)

## Estado del motor

Después de `engine.eval()`, llama a `engine.getState()` para acceder al estado más reciente.

## Salida de registros estructurados

`createStructuredRecord` transforma el estado del motor en un formato adecuado para el envío:

- `form_values` utiliza las claves de campo de forma predeterminada
- Las secciones repetibles se convierten en arrays de registros hijos
- Las secciones se omiten (solo son contenedores)

### Modo de clave de campo

Puedes cambiar a claves `data_name` mediante `fieldKeyMode`:

```js
const record = createStructuredRecord(state, fields, {
  fieldKeyMode: "data-name",
})
```

## Secciones repetibles

### Serialización cooperativa

Para un registro evaluado grande, `createStructuredRecordAsync` usa la misma transformación y cede
el control al entorno entre [filas](/es/core/fields/containers#repeatablesection). Mantén estables
el estado, los campos y las opciones hasta que termine; los controladores de envío de los bindings
ya controlan la instantánea seleccionada.

```js
const abortController = new AbortController()
const record = await createStructuredRecordAsync(
  snapshot,
  fields,
  {
    originalElements: schema.form.elements,
    mainRecordId: 0,
  },
  {
    signal: abortController.signal,
    budgetMs: 8,
    yieldToHost,
  },
)
```

El cuarto argumento controla la planificación y queda fuera del registro. `yieldToHost` es una
función opcional que devuelve una promesa para una tarea del entorno; sin ella, core usa un
temporizador. La cancelación rechaza la promesa con `AbortError` y no devuelve un registro parcial.
Este método no realiza cálculos, validación ni persistencia. Devuelve el mismo registro que
`createStructuredRecord`. Los formateadores de campos son síncronos.

Las secciones repetibles crean registros anidados. Utiliza `originalElements` para conservar la
estructura de anidamiento correcta al crear registros.

Sea cual sea la forma de asignar un valor, el registro enviado usa el mismo formato: SingleChoice/Boolean usa choice_value y other_value; MultiChoice usa choices_value y other_value. [Consulta el contrato de actualización de valores](/es/core/engine/value-updates).

## Cargar un registro guardado

Usa `buildFormRecordSnapshot(schema, record)` para convertir un registro guardado en valores con los
que form0 pueda trabajar, por ejemplo para volver a abrirlo. Devuelve `raw_values`, `repeatable` y
`timestamps`, la misma forma que `initialSnapshot`.

```jsx
import { buildFormRecordSnapshot } from "form0-core"
import { FormRenderer } from "form0-react"

export function SavedCase({ schema, savedRecord }) {
  const snapshot = buildFormRecordSnapshot(schema, savedRecord)

  return (
    <FormRenderer
      engineOptions={{ events: { recordKind: "existing" } }}
      schema={schema}
      initialSnapshot={snapshot}
    />
  )
}
```

Lanza un error si un campo tiene una forma incorrecta, como un campo de selección guardado como
texto simple. Para comprobar un registro guardado con el esquema, pasa `raw_values` y `repeatable` a
`createRecordEvaluator().prepareSubmission()`.

## Filas vacías guardadas

Una [fila](/es/core/fields/containers#repeatablesection) guardada permanece en el registro aunque
todas sus respuestas estén vacías. Por ejemplo, si un usuario añade una fila a un pedido, deja en
blanco los campos opcionales `product` y `quantity` y guarda la fila, el registro enviado la incluye
igualmente. Abreviada, la fila tiene este aspecto:

```json
{
  "id": "01a1924c-66df-79b8-bdf8-2100ba684129",
  "created_at": "2026-10-31T14:10:43.043Z",
  "form_values": { "product": null, "quantity": null }
}
```

Esto también se aplica a las filas anidadas. Una sección repetible sin filas permanece vacía.

Para impedir que se guarde una fila vacía, marca uno de sus campos como `required`. Para dejar una
fila fuera del registro, cancélala antes de guardarla o elimínala.
