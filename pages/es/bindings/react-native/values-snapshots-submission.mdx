## Estado inicial y restauración

Usa `initialValues` para inicializar un registro de la forma habitual. `overrideValues` tiene
prioridad y es útil para valores de la aplicación host que deben prevalecer. Para una restauración
completa, usa preferentemente `initialSnapshot`:

```jsx
<FormRenderer
  schema={schema}
  initialSnapshot={savedDraft}
  onSnapshotChange={(snapshot, change) => {
    if (change.dirty) queueLocalDraft(snapshot)
  }}
  onSubmit={uploadRecord}
/>
```

El snapshot mantiene juntos los valores sin procesar, las entradas repetibles anidadas y las marcas
de tiempo:

```js
{
  raw_values: {},
  repeatable: {},
  timestamps: {
    created_at_client: null,
    updated_at_client: null,
    created_at_server: null,
    updated_at_server: null,
  },
}
```

`onSnapshotChange(snapshot, meta)` informa primero de `{ kind: "seed", dirty: false }`; los cambios
posteriores del usuario usan `{ kind: "change", dirty }`.

## Guarda borradores o envía registros

Establece `primaryActionMode="save"` y proporciona `onSave(snapshot, meta)` para una acción de
guardado de borradores que no exija superar la validación. `meta` contiene el resumen de validación
actual y el estado de cambios sin guardar.

La acción de envío predeterminada valida primero. `onSubmit(record, meta)` recibe el registro
estructurado que se describe en [Salida y registros](/es/core/output-records), junto con los valores
sin procesar, el estado de las secciones repetibles, las marcas de tiempo y el resumen de
validación.

El binding no guarda ni sincroniza ninguno de los dos contenidos. Almacena los snapshots en local,
sube los registros, reintenta los fallos y resuelve los conflictos en la aplicación host.
