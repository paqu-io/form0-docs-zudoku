Los renderers personalizados cambian la presentación nativa sin sacar de `form0-core` los cálculos,
la visibilidad, la obligatoriedad ni la validación.

## Sustituciones por formulario

Pasa un mapa de renderers directamente a `FormRenderer` para un formulario concreto:

```jsx
import { FormRenderer } from "form0-react-native"
import { PhotoField } from "./photo-field.jsx"

;<FormRenderer schema={schema} renderers={{ PhotoField }} />
```

Un renderer recibe el campo y su estado de interacción evaluado:

```jsx
function PhotoField({ field, value, onChange, readOnly, required, error, inputProps }) {
  // Render application-owned capture, preview, and removal controls.
}
```

Conserva las propiedades aplicables de `inputProps` y llama a `onChange` con la forma de valor que
esperan el esquema y el envío.

## Proveedores, registros y sustituciones globales

Usa `FieldRegistryProvider` para sustituir renderers en un subárbol o
`createFieldRegistry({ includeDefaults, renderers })` para crear una instancia de registro
explícita. Las funciones de módulo `registerFieldComponent`, `unregisterFieldComponent` y
`resetFieldComponents` modifican el registro predeterminado compartido; resérvalas para el código de
arranque o las pruebas.

Solo se pueden registrar los tipos de campo que declara `form0-core`. Un tipo de campo nuevo debe
definirse primero en el núcleo; un renderer nativo no basta para ampliar el contrato del esquema.
