---
title: Solución de problemas de React
description: Diagnostica problemas habituales de instalación, renderizado, estilos y workers en form0-react.
---

<PageBadges />

## El formulario aparece sin estilos

Importa `form0-react/index.css` una sola vez en el punto de entrada de la aplicación. Comprueba que
el bundler permita importar CSS desde las dependencias.

## Un campo indica que no es compatible

Comprueba que el tipo aparezca en el [Catálogo de campos del núcleo](/es/core/fields/catalog). Si el
tipo es conocido pero lo sustituyes a propósito, verifica que el componente esté registrado en el
mismo subárbol de `FieldRegistryProvider` que `FormRenderer`.

## El esquema falla al renderizarse

`FormRenderer` valida `schema.form` y requiere `form.elements`. Usa
[`form0 validate`](/es/cli/schemas/validate-preview) antes de cargar el esquema en la aplicación.

## El modo worker no puede cargar el worker

Primero vuelve a `engineMode="main-thread"`. Con Vite, mantén el constructor del worker analizable
de forma estática y excluye `form0-react` de la optimización de dependencias, como hace el starter
web mantenido. Otros bundlers deben admitir module workers ESM basados en
`new URL(..., import.meta.url)`.

Las opciones personalizadas `workerUrl` y `createWorker` no forman parte de la API pública de
`FormRenderer`.

## Los cambios no aparecen durante el desarrollo local del paquete

Vuelve a compilar `form0-react`, reinicia el servidor de desarrollo de la aplicación que lo usa y,
si es necesario, borra solo la caché de dependencias de ese bundler. Vite puede conservar una copia
optimizada de un paquete enlazado o instalado anteriormente.

## El envío no se ejecuta

Comprueba que `onSubmit` sea una función, que el formulario esté en modo de edición, que
`submitBlockedReason` esté vacío y que el resumen de validación no tenga errores. En los overlays
que devuelven una promesa, gestiona el rechazo para que la aplicación pueda mostrar el fallo
mientras el overlay sigue abierto.
