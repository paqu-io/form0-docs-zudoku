## La forma es unstyled

Importe `form0-react/index.css` una vez en el punto de entrada de la aplicación. Confirme que el empaquetador permite
CSS importa desde dependencias.

## Un campo dice que no es compatible

Confirme que el tipo está listado en el [Catálogo de campos del núcleo](/es/core/fields/catalog).
conocido pero reemplazado intencionalmente, verifique que el componente esté registrado en el mismo
Subárbol `FieldRegistryProvider` como `FormRenderer`.

## El schema falla durante el renderizado

`FormRenderer` valida `schema.form` y requiere `form.elements`. Uso
[`form0 validate`](/es/cli/schemas/validate-preview) antes de cargar el schema en la aplicación.

## El modo de trabajador no puede cargar el worker

Primer retorno a `engineMode="main-thread"`. Para Vite, mantenga el constructor worker estáticamente
analizar y excluir `form0-react` de la optimización de dependencias como se muestra en la web mantenida
starter. Otros agrupadores deben admitir el módulo ESM workers basado en `new URL(..., import.meta.url)`.

Las opciones personalizadas `workerUrl` y `createWorker` no son parte del público `FormRenderer` API.

## Las actualizaciones no aparecen durante el desarrollo del paquete local

Reconstruir `form0-react`, reiniciar el servidor de desarrollo de consumo, y borrar solo que el bundler
Vite puede conservar una copia optimizada de un enlace o una copia anterior
paquete instalado.

## La sumisión no se ejecuta

Compruebe que `onSubmit` es una función, el formulario está en modo de edición, `submitBlockedReason` está vacío y
el resumen de validación no tiene errores. Para las superposiciones que devuelven una promesa,
La aplicación puede presentar el fallo mientras la superposición permanece abierta.
