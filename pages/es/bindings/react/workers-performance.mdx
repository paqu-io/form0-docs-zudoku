## Ejecución del motor

El valor predeterminado, `engineMode="main-thread"`, evalúa el motor del formulario en el hilo de la
interfaz. Usa `engineMode="worker"` para llevar la evaluación del motor al module worker incluido en
el paquete cuando haya Web Workers disponibles:

```jsx
<FormRenderer schema={schema} engineMode="worker" />
```

Vite admite el patrón de module worker estático que usa el paquete y genera el worker durante la
compilación de producción. El starter mantenido de Vite excluye `form0-react` de la optimización de
dependencias para que este worker siga disponible.

La API pública de `FormRenderer` no acepta una URL de worker personalizada ni una factoría de
workers. Las aplicaciones que usen otro bundler deben confirmar que admite
`new Worker(new URL("./worker.js", import.meta.url), { type: "module" })`; en caso contrario, usa el
modo predeterminado en el hilo principal.

Si el navegador no admite Workers, el binding vuelve a ejecutar el motor en el hilo principal.

## Modo de almacenamiento en React

`engineStoreMode="snapshot"` clona el snapshot del motor en el estado de React y es el valor
predeterminado. `engineStoreMode="selector"` usa suscripciones por campo para reducir los
rerenderizados generales.

Trata el modo selector como una optimización: antes de adoptarlo, verifica en la aplicación de
destino los errores de los campos, los resúmenes de navegación, las secciones repetibles y el
comportamiento del envío.

## Opciones del motor en modo worker

Los callbacks de aplicación (`onDiagnostics`, `onWarning`, `onUpdate`, `onOperations`) permanecen en el host; no se serializan al worker. El esquema, los valores y la configuración deben admitir clonación estructurada. Los helpers con funciones y otra configuración no clonable se rechazan con un error claro de inicialización antes de enviar una solicitud: usa `engineMode="main-thread"` para helpers con funciones. Un fallo de configuración no cambia el modo solicitado ni descarta helpers silenciosamente. Se conserva la alternativa existente cuando Worker no está disponible. Los mensajes de diagnóstico se aceptan una vez por ámbito y evaluación activos; las generaciones obsoletas no restauran hallazgos anteriores. Consulta [FormRenderer](/bindings/react/form-renderer) para la interfaz compartida.

Si sustituyes el esquema o los valores iniciales mientras el worker se está inicializando, vuelve a montar `FormRenderer` para inicializar la sustitución de forma predecible. Se conserva la protección de inicialización en curso: los ámbitos de diagnóstico obsoletos terminan inmediatamente, pero los informes no programan una evaluación adicional. Una colección activa vacía no demuestra que la sustitución se haya evaluado.

## Eventos gestionados y validación personalizada

Las solicitudes/resultados gestionados son datos clonables. Callbacks y alertas quedan en el host; cada respuesta se consume una vez y las generaciones anteriores se rechazan. La promesa espera delegación y actualizaciones predeterminadas del worker. Los helpers con funciones no se admiten en worker; usa main-thread. Validación y notificaciones de ciclo no añaden evaluaciones.
