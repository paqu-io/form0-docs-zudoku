## Ejecución del motor

El valor predeterminado, `engineMode="main-thread"`, evalúa el motor del formulario en el hilo de la
interfaz. Usa `engineMode="worker"` para llevar la evaluación del motor al module worker incluido en
el paquete cuando haya Web Workers disponibles:

```jsx
<FormRenderer schema={schema} engineMode="worker" />
```

Vite admite el patrón de module worker estático que usa el paquete y genera el worker durante la
compilación de producción. El starter mantenido de Vite excluye `form0-react` de la optimización de
dependencias para que este worker siga disponible.

La API pública de `FormRenderer` no acepta una URL de worker personalizada ni una factoría de
workers. Las aplicaciones que usen otro bundler deben confirmar que admite
`new Worker(new URL("./worker.js", import.meta.url), { type: "module" })`; en caso contrario, usa el
modo predeterminado en el hilo principal.

Si el navegador no admite Workers, el binding vuelve a ejecutar el motor en el hilo principal.

## Modo de almacenamiento en React

`engineStoreMode="snapshot"` clona el snapshot del motor en el estado de React y es el valor
predeterminado. `engineStoreMode="selector"` usa suscripciones por campo para reducir los
rerenderizados generales.

Trata el modo selector como una optimización: antes de adoptarlo, verifica en la aplicación de
destino los errores de los campos, los resúmenes de navegación, las secciones repetibles y el
comportamiento del envío.
