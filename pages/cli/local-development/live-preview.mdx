Run `form0 serve [schema]` to start the local preview server. It uses port `3030` and binds to
`localhost` by default; `--port` and `--host` override those values.

The preview server is a development tool. Use trusted projects and connectors, and only expose it
to a trusted network.

## Calculation diagnostics in the browser

In form0-cli 0.6.0 and later, the server returns structured diagnostics alongside evaluated state.
The browser console shows new or changed findings, resolved findings, and problems that recur;
identical evaluations do not repeatedly print them. Nested-row findings identify their repeatable
path and existing row ID, or explicitly show a positional reference when no ID exists.

Use `form0 serve [schema] --no-diagnostics` to suppress CLI-owned calculation reports and built-in
preview console output. Diagnostics are still collected. An app started with `serve --app` keeps
its own application reporting policy.

A completed calculation evaluation still returns state when diagnostics contain errors. Field
validation, event operations, submission policy, and draft saving retain their own behavior;
diagnostics do not add form alerts or submission blockers.

## Portable preview events (CLI 0.7.0+)

The current built-in preview uses core's shared record evaluation and requires core 0.8.1 or later
within the supported 0.8.x range. Fresh previews enable lifecycle events and select **New record**.
In **Form Settings → Record preview**, choose **Existing record** or **Open read-only** as needed.
Classification selects lifecycle hooks; it does not load a database record. Explicitly saved legacy
opt-outs remain respected. **Advanced event settings** contains the lifecycle compatibility switch
and optional focus/blur/click subscriptions. Read-only opening runs load only; changing configuration
starts a fresh session with accepted values. `serve --app` retains app-owned event options.
React and Native expose these options through their APIs, with no preview-settings UI; their current
opt-in defaults remain unchanged.

Initialization evaluates effective values, runs `load-record`, then the applicable `new-record` or
`edit-record`. User changes run after queued updates settle; defaults, calculations and `SETVALUE()`
do not generate extra changes. Enabled status uses `change-status`; optional text/numeric focus and
blur, and supported hyperlink click, are selected separately.

Submit follows built-in/custom validation → `save-record` once → validation again only if values
changed → final serialization → existing connector submission. Synchronous `INVALID(message)` adds
a scope-level summary message without changing intrinsic `state.errors`. Calculation diagnostics
alone do not block submission. **Prepare draft** produces a raw snapshot and possibly invalid
summary in the console, with no connector call or persistence. There are no `saved-*` schema events.

Inline rows offer **Edit**, **Save row** and **Cancel row**. They use repeatable lifecycle hooks and
staged values: Save validates/prepares before accepting; Cancel discards staged nested edits.
Handlers read permitted ancestor/main fields and write only their current row. Collapsing changes
presentation only. Accepted add/edit/remove notifies the owning repeatable; later notification
issues are reported separately from the already accepted preparation. Closed rows use the shared submission preparation described below without replaying their editing lifecycle.

The active developer controller is `window.form0PreviewEvents`. Its promise-based `dispatch()` and
`prepareSave({ intent: 'submit' | 'draft' })` return findings/issues and finish accepted presentation;
preparation itself neither submits nor closes. Row targets supply complete `instancePath` and the
observed `scopeId` (also shown as `data-preview-scope-id`). Positional paths require that ID. Metadata
is JSON; executable configuration and native file handles are rejected. Saved values contain no
scope or diagnostic metadata. Cancel/Close notify before retirement; reload/forced disposal only
retires. Reopen starts a fresh session. This does not change terminal run/validate exit behavior.

**Advanced preview actions** groups **Prepare draft**, **Cancel record** and **Close record** in a
collapsed section. Preparing a draft is inspection only and never saves it to a connector. Disabled
nested row controls explain which parent editor must be opened first. Submit logs the expandable
final record and individual connector outcomes. With no connector configured, it explicitly reports
that the record is prepared for preview only; a connector or persistence failure is not a saved result.

## Shared preparation and a host storage adapter

Preview uses shared freshness and built-in submission validation whether managed lifecycle is
enabled or disabled. Opting out keeps managed custom validation/save hooks disabled. Closed-row
load, edit, change, save and unload events are not replayed. Open row edits must be accepted or
cancelled before root preparation.

`createApp()` accepts server-owned `submissionOptions` and an optional `storageAdapter`. Retention
requires the adapter and explicit `allowRetain`; browser requests cannot grant that permission.
The adapter implements async `load(identity)` returning `{ record, freshness }` or `null`, and
`save(identity, { record, freshness })`. `record` uses the existing structured record shape. The
session uses `recordIdentity` or `recordOptions.mainRecordId` to restore a saved identity, including
zero. The example atomically replaces a local envelope; production hosts own revision/conflict policy.

Adapter success acknowledges the preparation. Rejection, partial persistence or failed connector
submission leaves the attempt unsaved. Existing connectors continue receiving the same record
payload and gain no freshness-storage responsibility. Preparation-only clients explicitly acknowledge
a successful external save. Review details are paged through `getSaveChanges()` and decisions are
all-or-none.

```js
import { createApp } from "form0-cli/src/server/express-server.js"
import { createFilePreviewStorage } from "form0-cli/src/server/preview-events/file-storage.js"

const app = createApp(getSchema, getSchemaSource, projectDir, {
  submissionOptions: { mode: "confirm", allowRetain: true },
  storageAdapter: createFilePreviewStorage(previewStorageDirectory),
})
```
